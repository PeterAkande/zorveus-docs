Webhooks push real-time HTTP `POST` notifications from Zorveus to your server when important events happen in your organization, such as a wallet top-up settling, a customer hitting a spending cap, or a BYOK provider key running out of quota.

---

## 1. Set up a webhook endpoint

1. Open your organization in the [Zorveus dashboard](https://app.zorveus.com) and go to **Webhooks**.
2. Enter your HTTPS endpoint URL and choose the events you want to receive.
3. Enable the endpoint and copy the **Signing Secret** (`HMAC SHA-256`). Store it as `ZORVEUS_WEBHOOK_SECRET` on your server.

You can pause delivery at any time by toggling the endpoint off, or rotate the secret with **Rotate Secret** if it is compromised. After rotating, update `ZORVEUS_WEBHOOK_SECRET` on your server right away so signature verification continues to pass.

---

## 2. Verify webhook signatures

Every delivery includes these headers:

- `Content-Type: application/json`
- `User-Agent: Zorveus/1.0`
- `X-Zorveus-Signature: t=<unix_timestamp>,v1=<hex_hmac_sha256>`

Example signature header:

```text
X-Zorveus-Signature: t=1756249200,v1=5d41402abc4b2a76b9719d911017c59205d41402abc4b2a76b9719d911017c5920
```

Verify every request before parsing or acting on its JSON:

1. Extract `t` (Unix timestamp in seconds) and `v1` (64-character hex digest) from `X-Zorveus-Signature`.
2. Reject malformed values and timestamps more than 5 minutes (300 seconds) away from the current time to block replay attacks.
3. Concatenate `t`, a literal `.`, and the **raw HTTP request body bytes** (`<t>.<raw_body>`). Do not parse and reserialize the JSON before hashing.
4. Compute `HMAC-SHA256` using your `ZORVEUS_WEBHOOK_SECRET` and compare against `v1` with a constant-time comparison function.

<CodeGroup titles={["Node.js (Express)", "Python (FastAPI / Flask)"]}>

```javascript
const crypto = require("crypto");

// In Express, mount express.raw({ type: "application/json" }) on your webhook route
// so req.body stays a Buffer of the original bytes.
function verifyZorveusSignature(rawBody, sigHeader, secret) {
  if (!sigHeader || !Buffer.isBuffer(rawBody)) return false;

  const parts = {};
  for (const item of sigHeader.split(",")) {
    const idx = item.indexOf("=");
    if (idx !== -1) {
      parts[item.slice(0, idx).trim()] = item.slice(idx + 1).trim();
    }
  }

  const timestamp = parts.t;
  const signature = parts.v1;
  if (!timestamp || !signature) return false;
  if (!/^\d{1,12}$/.test(timestamp) || !/^[a-f0-9]{64}$/i.test(signature)) return false;

  const signedAt = Number(timestamp);
  if (!Number.isSafeInteger(signedAt) || Math.abs(Date.now() / 1000 - signedAt) > 300) {
    return false;
  }

  const signedPayload = Buffer.concat([
    Buffer.from(`${timestamp}.`, "utf-8"),
    rawBody,
  ]);

  const expected = crypto
    .createHmac("sha256", secret)
    .update(signedPayload)
    .digest("hex");

  const sigBuf = Buffer.from(signature.toLowerCase(), "utf-8");
  const expBuf = Buffer.from(expected, "utf-8");
  if (sigBuf.length !== expBuf.length) return false;

  return crypto.timingSafeEqual(sigBuf, expBuf);
}
```

```python
import hashlib
import hmac
import re
import time


def verify_zorveus_signature(raw_body: bytes, sig_header: str, secret: str) -> bool:
    if not sig_header:
        return False

    header_parts = {}
    for part in sig_header.split(","):
        if "=" in part:
            key, value = part.split("=", 1)
            header_parts[key.strip()] = value.strip()

    timestamp = header_parts.get("t")
    received_sig = header_parts.get("v1")
    if not timestamp or not received_sig:
        return False
    if not re.fullmatch(r"[0-9]{1,12}", timestamp) or not re.fullmatch(r"[a-fA-F0-9]{64}", received_sig):
        return False
    if abs(time.time() - int(timestamp)) > 300:
        return False

    signed_payload = f"{timestamp}.".encode("utf-8") + raw_body
    expected = hmac.new(
        secret.encode("utf-8"),
        signed_payload,
        hashlib.sha256,
    ).hexdigest()

    return hmac.compare_digest(received_sig.lower(), expected)
```

## 3. Event catalog

| Area | Event type | When it fires |
| :--- | :--- | :--- |
| **Wallet** | `wallet.low_balance` | Available organization wallet balance drops to or below your alert threshold. |
| **Wallet** | `wallet.payment_credited` | A wallet top-up payment is verified and credited to your organization wallet. |
| **Wallet** | `wallet.payment_failed` | A wallet top-up payment attempt fails. |
| **Customer** | `product_user.cap_reached` | A request with a customer ID is blocked by a customer cap or API key cap for the period. |
| **Customer** | `product_user.credits_granted` | Credits are granted to a customer in one of your apps. |
| **API key** | `app_connection.cap_reached` | A request without a customer ID is blocked by an API key spending cap for the period. |
| **BYOK** | `provider_credential.quota_exhausted` | One of your BYOK provider keys hits rate limiting or quota exhaustion. |

### Envelope structure

Every event uses the same top-level JSON envelope:

- `id`: Stable event ID across retries. Use this field to deduplicate deliveries.
- `event`: Event type name (for example, `wallet.payment_credited`).
- `org_id`: Organization that owns the event.
- `timestamp`: UTC timestamp for the delivery attempt (changes on retries; do not use for deduplication).
- `data`: Event-specific payload fields.

## 5. Retries, delivery logs, and manual replay

Zorveus delivers events asynchronously with a 10-second request timeout:

| Response from your server | Behavior |
| :--- | :--- |
| `2xx` | Marked `succeeded`. |
| `429`, `5xx`, timeout, or connection error | Retried with exponential backoff up to 10 total attempts. |
| Other `4xx` (`400`, `401`, `403`, `404`) | Marked `failed` immediately without retrying. |
| Endpoint disabled | Skipped without making an HTTP call. |

In the dashboard under **Webhooks → Deliveries**, you can filter deliveries by status (`succeeded`, `failed`, `pending`, `retrying`), search by event ID or error message, inspect the sent JSON payload and attempt count, and click **Retry** on any failed delivery.

---

## 6. Receiver checklist

- **Acknowledge fast**: Persist the event to your queue or database and return HTTP `200` or `204` well within the 10-second timeout. Run slow follow-up work asynchronously.
- **Deduplicate on `id`**: Delivery is at-least-once and order is not guaranteed. Ignore events whose `id` you already processed; never deduplicate on `timestamp` or `X-Zorveus-Signature`.
- **Match customers by `external_user_id`**: On `product_user.*` events, look up your customer by `data.external_user_id` and check `data.app_id` and `org_id`.
- **Recheck live balance instead of caching locks**: A `product_user.cap_reached` event reports one blocked request, not a permanent lock. When the customer retries or receives credits, check [available allowance](/startups/check-allowance) directly.
- **Keep BYOK alerts separate from customer caps**: Treat `provider_credential.quota_exhausted` as an upstream provider key issue; see [Key priority, rotation, and fallback](/startups/automatic-routing).
