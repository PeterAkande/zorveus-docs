title: Security

Follow these rules to keep your credentials, customer data, and billing safe:

## Credentials and server boundaries

- **Keep server secrets off the client**: Never put Business API keys (`zrv_...`), routing keys (`zrv_route_...`), service keys (`zrv_svc_...`), confidential OAuth client secrets (`zrv_client_secret_...`), or webhook signing secrets in browser code, mobile apps, or source control.
- **Use least privilege**: Give each API key only the allowed models and spending caps it needs, and give service keys only `product_users:read` unless your backend must write profiles or grant credits.
- **Store secrets on creation**: Raw API keys, service keys, and client secrets are shown once when created. Save them directly into your secret manager.
- **Rotate leaked credentials immediately**: Replace compromised keys in the dashboard and revoke the old ones. See [Security and connected apps](/account-and-organizations/account-security).

## Logging and redaction

Zorveus encrypts stored BYOK provider credentials at rest. On your side, strip `Authorization` headers, `x-api-key` headers, OAuth authorization codes, PKCE verifiers, client secrets, and webhook signing secrets from application logs, traces, and support tickets.

## OAuth and webhooks

- **OAuth PKCE**: Always generate a fresh `state` and S256 PKCE `code_verifier` for each login attempt, verify `state` on callback, register exact callback URLs, and exchange codes from your backend for confidential apps. See [Connect users and exchange tokens](/oauth/token-exchange).
- **Webhooks**: Verify `X-Zorveus-Signature` against the raw HTTP body bytes with a constant-time comparison and reject timestamps older than 5 minutes before processing the payload. See [Webhooks](/platform/webhooks).
