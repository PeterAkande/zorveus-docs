---
title: Authentication and credentials
description: Choose the credential for inference, product-user management, or OAuth.
---

Use the credential issued for the operation you are calling

| Credential | Where to send it | Use |
| --- | --- | --- |
| Inference key, `zrv_...` | `Authorization: Bearer zrv_...` | Model requests, key-scoped model discovery, and key usage |
| Routing key, `zrv_route_...` | The same Bearer header, with an optional `X-Zorveus-Key-Alias` selector | Select a plan's inference key. See [routing keys](/startups/routing-keys) |
| OAuth access token, `zrv_...` | The same Bearer header | Inference funded by the user's authorized connection |
| Service key, `zrv_svc_...` | `Authorization: Bearer zrv_svc_...` | [Product-user profiles, credits, and allowance](/api-reference/product-users) from your server |
| OAuth client ID and secret | Form body at `/oauth/token` and `/oauth/revoke` | Authenticate a confidential OAuth app. Public clients omit the secret |

Native Anthropic SDKs can send the inference key in `x-api-key`. OpenAI-compatible clients use `Authorization: Bearer ...`

Keep Business inference keys, routing keys, service keys, provider secrets, and confidential client secrets on your server. For a browser OAuth app, use a public client with PKCE and the user's scoped token. CORS support does not make a shared Business key safe to publish

## Attribute customer requests

Send `X-Zorveus-External-User-ID` with your authenticated customer's ID. For subscription cycles, use `X-Zorveus-Allowance-Starts-At`. For plan selection through a routing key, use `X-Zorveus-Key-Alias`. See [Product-user metadata](/inference/product-user-metadata) for body alternatives and precedence

The key or selected connection identifies your app and funding organization. Do not invent headers to override the app or organization

## Track responses and events

Successful gateway responses can include `x-zorveus-request-id` and, when a reservation exists, `x-zorveus-reservation-id`. Save these with your own request ID for support. Not every rejected request creates a reservation

Outbound webhooks include `X-Zorveus-Signature`. Verify it against the raw request bytes before processing the event. See [Webhooks](/platform/webhooks)
