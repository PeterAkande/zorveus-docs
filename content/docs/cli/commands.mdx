## Structured output and exit codes

Pass `--json` for machine-readable output and `--non-interactive` in scripts so the CLI never opens a browser or prompts for input:

```sh
zorveus status --config zorveus.json --json --non-interactive
```

JSON responses always include `version`, `ok`, `command`, and either `result` or `error`. Diagnostics go to stderr (use `--log-level debug` for extra detail; secrets are always redacted). `status` exits `0` after a successful read even when drift exists, so check `result.in_sync` in scripts.

| Exit code | Meaning |
| :--- | :--- |
| `0` | Command succeeded. |
| `1` | Operational failure or incomplete logout/login replacement. |
| `2` | Invalid arguments or invalid manifest. |
| `3` | Login or additional permissions required. |
| `4` | Target mismatch, stale plan, or modified manifest. |
| `5` | Incomplete apply or uncertain mutation outcome. |

## Commands

| Command | Purpose |
| :--- | :--- |
| `login`, `whoami`, `logout` | Manage per-organization CLI sessions in your OS credential store. |
| `update` | Install the latest published CLI release or a specific `--version`. |
| `setup` | Interactive wizard to create or edit an app, customer allowance plans, and optional routing key. |
| `init`, `validate` | Create and validate a manifest offline. |
| `plan`, `apply` | Preview and apply manifest changes (or resume an interrupted apply). |
| `retrieve` | Print a saved secret from the OS credential store by manifest reference or backend ID. |
| `status` | Compare the manifest against remote resources and check drift. |
| `destroy` | Preview and tear down an app and all credentials listed in its manifest. |
| `state init`, `state inspect`, `state pull`, `state unlock` | Initialize, inspect, back up, and unlock S3-compatible durable state. |
| `import` | Adopt an existing Zorveus app into a new manifest. |
| `clone` | Copy a manifest offline without organization, state, or app-owned IDs. |
| `promote` | Merge source settings into an existing target manifest offline while keeping target IDs. |
| `apps list` | List apps in the selected organization. |
| `service-keys list`, `service-keys revoke` | Inspect and revoke organization service keys. |
| `mcp serve` | Start the local stdio MCP server for coding agents. |
| `completion` | Generate shell completion scripts (`bash`, `zsh`, `fish`, `powershell`). |

## Command flags

| Command | Flags |
| :--- | :--- |
| `login` | `--scope`, `--dashboard-url`, `--timeout` (default `5m`), `--no-browser` |
| `update` | `--version` (optional release tag such as `v0.1.0`) |
| `setup` | `--config` (default `zorveus.json`), `--name`, repeatable `--model`, `--credits-per-usd` (default `100`), repeatable `--plan`, `--routing-key`, `--default-selector`, `--yes`, `--allow-delete` |
| `init` | `--config` (default `zorveus.json`), `--name` (default `My app`), repeatable `--model` (default `*`), `--starter` (`saas`), `--credits-per-usd` (default `100`), repeatable `--plan` |
| `validate`, `status` | `--config` (default `zorveus.json`) |
| `plan` | `--config`, optional `--from`, `--keep-names` (with `--from`), optional `--out` |
| `apply` | `--plan` (default `zorveus.plan.json`), `--config`, `--resume`, required `--yes`, optional `--allow-delete` |
| `retrieve` | Positional `<item-or-id>` (such as `keys.backend`, `routingKeys.primary`, `serviceKeys.customers`, `app`, or backend ID), `--config` (default `zorveus.json`) |
| `destroy` | `--config` (default `zorveus.json`), optional `--out`, `--dry-run`, `--yes` |
| `state init` | `--config` (default `zorveus.json`), `--copy-local`, `--force` |
| `state inspect` | `--config` (default `zorveus.json`) |
| `state pull` | `--config` (default `zorveus.json`), `--out` (default `zorveus.state.backup.json`) |
| `state unlock` | `--config` (default `zorveus.json`), required `--lock-id`, required `--yes` |
| `import` | Required `--app-id`, `--config` (default `zorveus.json`; destination must be new) |
| `clone` | Required `--from`, required `--to` (must be new), optional `--name` |
| `promote` | Required `--from`, required `--to` (must contain an existing `app.id`), optional `--keep-names` |
| `apps list` | `--limit` (`1` to `1000`, default `1000`) |
| `service-keys list` | No command-specific flags |
| `service-keys revoke` | Required `--id`, required `--yes` |
| `mcp serve` | Optional `--directory` (default `.`) |
| `completion` | Shell argument: `bash`, `zsh`, `fish`, or `powershell` |

## Global flags

| Flag | Behavior |
| :--- | :--- |
| `--org` | Select an organization ID explicitly (must match any manifest or plan `organizationId`). |
| `--state-config` | Path to a separate JSON file containing the `_state` backend block. |
| `--json` | Write one structured JSON result (ignored by `mcp serve`, which outputs MCP messages). |
| `--non-interactive` | Never open a browser or wait for terminal prompts. |
| `--local` | Target local API (`http://localhost:8000`) and dashboard (`http://localhost:3000`). |
| `--api-url` | Override or require a specific management API origin. |
| `--allow-insecure-loopback` | Permit custom `http://` origins on localhost or loopback IPs. |
| `--log-level` | `debug`, `info` (default), `warn`, or `error`. |
| `--no-color` | Disable terminal colors. |
| `--help` | Show usage and flags. |

## Service keys

Declare `serviceKeys` in a manifest to create organization service keys, or inspect and revoke them directly:

```sh
zorveus service-keys list
zorveus service-keys revoke --id service_example --yes
```

Revocation applies across the entire organization. Runtime scopes on a service key (`product_users:read`, `product_users:write`) are separate from the management permissions approved during `zorveus login`.

## Troubleshooting

| Symptom | Fix |
| :--- | :--- |
| `zorveus` not found | Add `~/.local/bin` (macOS/Linux) or `%LOCALAPPDATA%\Zorveus\bin` (Windows) to `PATH`. See [Install and update](/cli/installation). |
| `login_required` | Run `zorveus login` (add `--local` for a local backend, or `--org` to sign in to a specific organization). |
| `authorization_required` | Sign in again and approve the missing scopes, and verify your [organization role](/account-and-organizations/organizations#member-roles). |
| Credential store unavailable | Unlock Keychain (macOS), Secret Service (Linux), or Credential Manager (Windows) and retry. |
| `stale_plan` or manifest changed | Run `zorveus plan` again to generate a fresh plan before applying. |
| `apply_pending` or `apply_incomplete` | Keep the saved plan and `.zorveus/` (or durable state), inspect the journal, and resume with `zorveus apply`. |
| Durable state locked | Confirm no other deployment is running, run `zorveus state inspect`, then `zorveus state unlock --lock-id <id> --yes`. |
| BYOK input shows `unverified` | Export the environment variable named in `secretFromEnv` in the shell running `status`. |
| `mcp serve` prints nothing | It is waiting for stdio MCP messages; configure your MCP client to launch it instead of running it interactively. |
