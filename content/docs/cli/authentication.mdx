---
title: Sign in and select an organization
description: Authorize the CLI through browser consent, manage multiple organization logins, and target local or custom backends.
---

```sh
zorveus login
zorveus whoami
zorveus apps list
```

`zorveus login` opens the Zorveus dashboard in your browser (`https://app.zorveus.com`, targeting `https://api.zorveus.com`), where you pick an organization and approve CLI access.

By default, login requests all CLI management permissions (apps, API keys, routing keys, spending caps, service keys, and BYOK provider credentials). To request fewer permissions, pass `--scope`:

```sh
zorveus login --scope "apps:read"
```

Use `zorveus login --no-browser` to print the authorization URL instead of opening a browser automatically.

---

## Work with multiple organizations

The CLI saves a **separate login per API origin and organization** in your OS credential store. Signing in to a second organization keeps your earlier login intact. Signing in to the same organization on the same API origin replaces only that session.

After each sign-in, the CLI asks **Use this organization as your default?**. Answer `n` to keep your current default.

To authorize multiple organizations and target one explicitly:

```sh
zorveus login --org org_development
zorveus login --org org_production
zorveus apps list --org org_production
zorveus whoami --org org_development
```

Commands pick the organization in this order:

1. Explicit `--org`, when passed.
2. `organizationId` recorded in the manifest or saved plan (set automatically by `setup`, `import`, and `apply`).
3. The only saved organization matching the API origin.
4. Your saved default organization for that API origin.

An explicit `--org` must match the manifest's `organizationId`. It cannot move existing resources to a different organization.

Organization IDs, cached names, API origins, and your default choice are indexed in `zorveus/logins.json` inside your OS user config directory. That index contains no tokens; every session's tokens stay in separate OS credential-store entries.

To sign out of the selected organization (leaving other saved organizations signed in):

```sh
zorveus logout
zorveus logout --org org_development
```

## Automatic sign-in and session renewal

In an interactive terminal, if a command needs a login or your session expires without renewal, the CLI explains why and waits for Enter before opening browser consent. Once you approve, the command picks up where it left off (`setup` keeps your answers; `apply` keeps its journal progress).

Non-interactive commands (`--non-interactive`), pipelines without a terminal, and MCP tools never open a browser. They return `login_required` or `authorization_required` instead; run `zorveus login` in a terminal and retry.

## Use a local or custom backend

To connect to a local Zorveus server (management API on port `8000`, dashboard on port `3000`):

```sh
zorveus login --local
zorveus whoami
zorveus apps list
```

`--local` targets `http://localhost:8000` and `http://localhost:3000`. Subsequent commands reuse the saved login's API origin.

For other environments, pass `--api-url` and `login --dashboard-url`. Custom `http://` origins must use loopback addresses and require `--allow-insecure-loopback`.

## Credential storage and roles

Login and secret storage require an available, unlocked OS credential store (Keychain on macOS, Secret Service on Linux, or Credential Manager on Windows). Tokens and generated secrets never appear in manifests or command output.

Browser consent grants OAuth scopes to the CLI, and your organization role still controls which actions you can run. See [Organizations and team access](/account-and-organizations/organizations#member-roles) for role permissions.
