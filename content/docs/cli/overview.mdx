Describe a Zorveus app in a JSON manifest (`zorveus.json`), preview changes with `zorveus plan`, and apply them with `zorveus apply`. Or run `zorveus setup` to walk through an interactive wizard. The CLI manages apps, API keys, routing keys, spending caps, OAuth settings, service keys, and BYOK provider credentials.

The CLI also includes a local MCP server (`zorveus mcp serve`) that exposes the same workflow to coding agents using your saved CLI login.

## How the files fit together

| File | Purpose |
| :--- | :--- |
| `zorveus.json` | Desired configuration for one app, plus `organizationId`, optional `_state`, and backend resource IDs written after apply. |
| `zorveus.plan.json` | Saved diff to review before applying changes. |
| `.zorveus/` | Local managed-resource state and apply recovery journals beside your manifest. |

Keep one manifest per app or environment (for example, `zorveus.dev.json` and `zorveus.prod.json`). Keep the resource IDs that `apply` writes back; you can edit display names without replacing resources. Resource object names such as `keys.backend` connect related settings and match resources across environments.

To share state across machines or CI runners, configure an S3-compatible `_state` backend; see [Durable state and destroy](/cli/state-and-destroy).

## Management vs. runtime credentials

Run `zorveus login` to authorize the CLI through browser consent. The CLI stores separate logins per API origin and organization in your OS credential store (Keychain on macOS, Secret Service on Linux, Credential Manager on Windows). Generated app secrets are also saved in your OS credential store and retrieved on demand with `zorveus retrieve`.

The CLI provisions configuration and policies. Your application's model requests, customer attribution, payments, and credit grants continue to use the [Inference API](/inference/overview) and [Product users](/startups/product-users). A spending cap sets a limit; it does not fund a wallet or buy credits.

See [Example manifests](/cli/examples), [Manifest reference](/cli/manifest), [Development and production](/cli/environments), and [Command reference](/cli/commands).
