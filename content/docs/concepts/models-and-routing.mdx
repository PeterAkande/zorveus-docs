title: Models and routing

Your request names a concrete model. The selected inference key determines which models you may use and which connection's spending policy applies

## Model access policies

Policies support an exact model ID, `provider/*`, or `*`. A provider wildcard matches model IDs beginning with that provider and a slash. Partial patterns such as `anthropic/claude-*` are not wildcard matches

Use `GET /v1/models` with the inference key to discover concrete IDs. With a routing key, include `X-Zorveus-Key-Alias` to inspect the selected member. The [public catalog](/api-reference/models) also describes capabilities, but it does not authorize a model for your key

## Plan selection

A [routing key](/startups/routing-keys) selects a member inference key using `X-Zorveus-Key-Alias` or `metadata.key_alias`. Your backend chooses the alias from the customer's subscription. This selects policy, not a different model unless your application also changes `model`

## Provider credential routing

For the requested model, Zorveus resolves eligible BYOK credentials or uses a managed route. [Automatic provider routing](/startups/automatic-routing) explains credential ordering and wallet fallback

A model policy permits access. It does not create a deployment, guarantee that every endpoint works for that model, or guarantee upstream capacity
