---
title: Troubleshooting
description: Diagnose authentication, model access, wallet funding, spending cap, service key, streaming, and OAuth errors.
---

Zorveus errors include a stable `code` and a safe `message`. Always log the HTTP status, `error.code`, and `x-zorveus-request-id` when diagnosing failures, and never log API keys, OAuth codes, provider secrets, or raw prompts.

```json
{
  "error": {
    "code": "zorveus_cap_exceeded",
    "message": "This request would exceed cap cap_123."
  }
}
```

---

## Authentication fails (`401` / `403`)

- `zorveus_malformed_or_missing_key` (`401`): `Authorization` header is missing or malformed.
- `zorveus_unknown_key` (`401`): Key does not exist in this environment.
- `zorveus_key_inactive` (`403`): API key or OAuth token was revoked or deactivated.

Confirm your request sends the full key in the header:

```http
Authorization: Bearer zrv_your_api_key
```

If the key was revoked or lost, create a replacement API key in the dashboard and update your backend secret. For a revoked user OAuth token, clear the token and ask the user to reconnect.

---

## A model is rejected (`400` / `403`)

- `zorveus_model_not_allowed` (`403`): The requested model is outside your API key's allowed-model policy.
- `zorveus_unsupported_model` (`400`): Zorveus does not recognize or route that model ID.

Call `GET /v1/models` with your API key to list the exact model IDs available to it, then either pick a returned model ID or update your key's model policy in the dashboard.

---

## Wallet funds are insufficient (`402`)

`zorveus_reservation_insufficient_balance` means the paying organization wallet cannot reserve the estimated charge (or BYOK platform fee). Top up the wallet in the dashboard or add an eligible BYOK key under **Provider Credentials**.

Adding a BYOK key does not guarantee it will be selected for every request. The credential must be active, match the model policy, and be accessible to your API key (`auto_resolve` or explicitly granted). See [Key priority, rotation, and fallback](/startups/automatic-routing).

---

## A spending cap blocks the request (`403`)

`zorveus_cap_exceeded` means an organization, API key, or product-user cap has been reached. Check which cap is named in the error message:

- On requests with `X-Zorveus-External-User-ID`, an API key cap applies separately to each customer.
- Under `enforce`, requests without a customer ID share a separate key-level spend total.
- A direct product-user cap applies to one specific customer in the app.

---

## Customer allowance blocks the request (`403`)

When a customer runs out of base cap plus active credits, the gateway returns HTTP `403 Forbidden`:

```json
{
  "error": {
    "message": "This request is estimated to cost 0.010000000000 USD, but the product user has 0.004720000000 USD of AI allowance remaining.",
    "code": "403",
    "provider_specific_fields": {
      "error": {
        "code": "zorveus_product_user_allowance_insufficient",
        "message": "This request is estimated to cost 0.010000000000 USD, but the product user has 0.004720000000 USD of AI allowance remaining.",
        "params": {
          "cap_amount": "0.010000000000",
          "remaining_base_allowance": "0.004720000000",
          "promotional_credit_balance": "0.000000000000",
          "available_allowance": "0.004720000000",
          "estimated_request_cost": "0.010000000000",
          "shortfall": "0.005280000000"
        }
      }
    }
  }
}
```

The OpenAI Python SDK raises `openai.PermissionDeniedError` for HTTP `403`. Check `error.provider_specific_fields.error.code` for `zorveus_product_user_allowance_insufficient` (or the legacy code `zorveus_product_user_credits_insufficient`), then grant credits, raise the cap, or prompt the customer to upgrade.

`enforce` mode does not require every request to carry a customer ID; enforce customer authentication in your own backend whenever attribution is mandatory.

## Customer details do not show up

Use the nested `metadata.product_user` shape:

```json
{
  "metadata": {
    "external_user_id": "usr_123",
    "product_user": {
      "display_name": "Ada Customer",
      "email": "ada@example.com",
      "metadata": { "plan": "pro" }
    }
  }
}
```

Fields such as `metadata.name`, `metadata.email`, and `metadata.user_metadata` are ignored. Flat compatibility fields (`product_user_display_name`, `product_user_email`, `product_user_metadata`) are also supported.

## A service-key request fails

Service keys (`zrv_svc_...`) authenticate routes on `https://api.zorveus.com` (without `/v1` or `/api/v1`):

| Code | Meaning | Fix |
| :--- | :--- | :--- |
| `zorveus_malformed_or_missing_service_key` | Header is missing or malformed. | Send `Authorization: Bearer zrv_svc_...`. |
| `zorveus_unknown_service_key` | No active service key matches. | Verify the secret or create a new service key. |
| `zorveus_service_key_inactive` | Service key was revoked or disabled. | Replace it with an active service key. |
| `zorveus_service_key_scope_required` | Service key lacks the route's required scope. | Create a key with `product_users:read` or `product_users:write`. |

---

## Streaming stops early

Read Server-Sent Events until `data: [DONE]` or stream close, buffering partial lines across network chunks. If the stream disconnects early, log `x-zorveus-request-id` and treat the response as incomplete. Only retry if your app can accept a second billable provider request.

---

## OAuth redirects fail

- `zorveus_redirect_uri_mismatch`: The `redirect_uri` sent to `/oauth/authorize` or `/oauth/token` does not match a registered URL character for character. Check scheme, host, port, path, query, and trailing slash.
- `zorveus_invalid_code_verifier`: Keep the original PKCE verifier in `sessionStorage` (public browser app) or server session (confidential backend) and send it with the same `redirect_uri` during token exchange.
- `zorveus_oauth_code_expired` / `zorveus_oauth_code_consumed`: Authorization codes expire in 10 minutes and can only be exchanged once. Start the connect flow again.

If an issue persists, send the request ID, endpoint, HTTP status, and error code to [support](/resources/support).
