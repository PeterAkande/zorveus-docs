title: Frequently asked questions
description: Quick answers about organizations, API keys, customer allowances, wallet funding, and BYOK.
---

## Which organization type do I need?

Use a **Business** organization (`startup` in the API) whenever your backend pays for AI, including solo projects. Use a **Developer** organization to register an OAuth app where end users connect their own Zorveus wallets. See [Integration options](/getting-started/overview).

## Which key do I send for model requests?

Send an API key (`zrv_...`), a routing key (`zrv_route_...`), or a user OAuth access token (`zrv_usr_...`). Service keys (`zrv_svc_...`) are for backend customer management only and cannot call models. See [API basics](/platform/base-urls#credentials).

## Does an API key cap give each customer their own allowance?

Yes. When you pass `X-Zorveus-External-User-ID` on requests from a Business organization, Zorveus tracks the API key's cap separately for each customer. For example, a `$10` monthly cap gives each customer their own `$10` monthly base allowance. Usage in that customer's current window carries across plan keys, so switching plans does not erase spend already used in that window.

Without a customer ID, an enforced API key cap applies to unattributed traffic as a shared total, while `enforce_if_present` skips per-customer checks. Always set the customer ID from your authenticated backend session. See [Configure product-user allowances](/startups/configure-product-user-allowances).

## Do I need to register customers before their first AI call?

No. Sending `X-Zorveus-External-User-ID` on a model request creates the customer record automatically. Before their first request, a service-key profile read returns `404` unless you pass `upsertIfMissing: true` (`X-Zorveus-Upsert-Product-User: true`) or call `createOrUpdate`.

## Do customer credit grants add money to my wallet?

No. Credit grants extend a customer's AI allowance inside your product. Your organization wallet or BYOK provider account still pays for actual model usage. See [Funding, caps, and credits](/concepts/funding-and-billing).

## Can I mix BYOK keys and wallet-funded requests?

Yes. Zorveus tries matching BYOK provider keys in priority order first. If no BYOK key matches, or if a BYOK key fails and `auto_fallback_to_wallet` is enabled with available wallet funds, Zorveus routes through its managed wallet path. See [Key priority, rotation, and fallback](/startups/automatic-routing).

## Is BYOK free?

Your upstream provider bills your provider account directly. Zorveus applies a configurable platform routing fee once monthly BYOK volume crosses your organization's free threshold. See [BYOK costs](/wallet-and-billing/byok-costs).

## Does Zorveus add latency?

Requests pass through the gateway for authentication, limit checks, routing, and usage recording. Total latency depends mostly on the model, upstream provider, and payload size, so benchmark with your real workload rather than assuming a fixed number.

## What does Zorveus store for each request?

Usage events store accounting and attribution metadata: model, token counts, prompt cache breakdown, costs, status, and identifiers. Check your upstream provider's data-retention policy before sending regulated or sensitive data.
