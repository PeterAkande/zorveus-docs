Send an attributed model request, then retrieve that customer's allowance with a service key. Complete the [Business quickstart](/getting-started/startup-quickstart) first so you have an app, a funded route, and an inference key

## Attribute a request

Send `X-Zorveus-External-User-ID: customer_42` with inference. Get the real value from your authenticated user or trusted worker state. The first request creates the product user for that app. Later requests with the same app and external ID use the same user

<CodeGroup titles={["Python", "TypeScript (@zorveus/sdk)"]}>

```python
import os
from openai import OpenAI

with OpenAI(
	api_key=os.environ["ZORVEUS_API_KEY"],
	base_url="https://api.zorveus.com/v1",
) as client:
	response = client.chat.completions.create(
		model=os.environ["ZORVEUS_MODEL"],
		messages=[{"role": "user", "content": "Hello"}],
		extra_headers={"X-Zorveus-External-User-ID": "customer_42"},
	)
	print(response.choices[0].message.content)
```

```typescript
import { Zorveus } from "@zorveus/sdk";

const client = new Zorveus({ apiKey: process.env.ZORVEUS_API_KEY! });
const response = await client.chat.completions.create({
	model: process.env.ZORVEUS_MODEL!,
	messages: [{ role: "user", content: "Hello" }],
	zorveusMetadata: { externalUserId: "customer_42" },
});

console.log(response.choices[0].message.content);
```

</CodeGroup>

For names, email, and custom metadata, see [Product-user metadata](/inference/product-user-metadata). Profile metadata such as `plan: "pro"` does not authorize a plan or select a different key

## Read the customer from your backend

Create a service key in the dashboard with `product_users:read`. Store it as `ZORVEUS_SERVICE_KEY` and set `ZORVEUS_APP_ID` to the app that owns the inference key. Run this on your server:

```bash
curl --fail-with-body --get https://api.zorveus.com/product-users/by-external-id \
	-H "Authorization: Bearer $ZORVEUS_SERVICE_KEY" \
	--data-urlencode "app_id=$ZORVEUS_APP_ID" \
	--data-urlencode "external_user_id=customer_42"
```

HTTP `200` returns the profile directly. Confirm that `external_user_id` matches and inspect `usage.this_period`, `allowance`, and `credits`. HTTP `404` means the app and external ID have no product user yet. A read does not create one

## Interpret the allowance

For a configured cap, `allowance.available_allowance` includes remaining base allowance plus available credits. `credits.available_credits` contains credits only. Use `allowance.period_end` for the reset date

An uncapped connection can return no allowance object. This does not mean the customer is exhausted. A positive allowance also does not guarantee the next request fits or that the organization has funds. Follow [Check available allowance](/startups/check-allowance) before adding a pre-request check

To create a profile before inference or update it outside a request, use `PUT /product-users/by-external-id` with `product_users:write`. To add allowance, follow [Credit grants](/startups/credit-grants). Neither operation deposits money into your organization's wallet
