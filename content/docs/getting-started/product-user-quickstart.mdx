Product users represent your application's customers. Pass your customer ID in each inference request so Zorveus can attribute usage and apply product-user credits or caps.

<KeyInserter type="inference" label="Inference Key Tester" placeholder="zrv_your_inference_key" />

---

## What you will build

This tutorial has two steps:

1. Send an inference request with `external_user_id`. Zorveus creates or updates the product user.
2. Query the product user and credit summary with a service key (`zrv_svc_...`).

---

## Step 1: Send product-user metadata

When Zorveus processes a request for an `external_user_id` it has not seen before, it **automatically creates the product user** in your startup workspace.

Subsequent requests with the same app and `external_user_id` resolve the same product user. Supplied profile fields can update that user, and settled requests contribute to usage totals.

<CodeGroup titles={["Python (ZorveusOpenAI)", "TypeScript (@zorveus/sdk)", "TypeScript (ZorveusOpenAI)", "TypeScript (Vercel AI SDK)", "Python (OpenAI SDK)", "cURL"]}>

```python
# pip install zorveus[openai]
from zorveus.openai import ZorveusOpenAI

# User is created automatically on their first inference call
client = ZorveusOpenAI(
    api_key="zrv_your_inference_key",
    external_user_id="usr_sara_101",
    display_name="Sara Connor",
    email="sara@example.com",
    user_metadata={"plan": "pro"}
)

response = client.chat.completions.create(
    model="openai/gpt-4.1-mini",
    messages=[{"role": "user", "content": "Hello!"}]
)

print(response.choices[0].message.content)
```

```typescript
// npm install @zorveus/sdk
import { Zorveus } from "@zorveus/sdk";

const client = new Zorveus({
  apiKey: "zrv_your_inference_key",
});

async function main() {
  const completion = await client.chat.completions.create({
    model: "openai/gpt-4.1-mini",
    messages: [
      { role: "user", content: "Summarize the latest trends in renewable energy." },
    ],
    zorveusMetadata: {
      externalUserId: "usr_sara_101",
      displayName: "Sara Connor",
      userEmail: "sara@example.com",
      metadata: { plan: "pro" },
    },
  });

  console.log(completion.choices[0].message.content);
}

main();
```

## Step 2: Query the user and credit balance

When you need to view user profile details, active credit grants, or remaining balance, use `ZorveusServiceClient` with an Organization Service Key (`zrv_svc_...`):

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "cURL"]}>

```typescript
import { ZorveusServiceClient } from "@zorveus/sdk";

const service = new ZorveusServiceClient({
  apiKey: "zrv_svc_your_service_key",
});

const userInfo = await service.productUsers.getByExternalId({
  appId: "app_123",
  externalUserId: "usr_sara_101",
});

const credits = await service.productUsers.getCreditSummaryByExternalId({
  appId: "app_123",
  externalUserId: "usr_sara_101",
});

console.log("Display name:", userInfo.display_name);
console.log("Available credits:", credits.available_credits);
```

```bash
curl -X GET "https://api.zorveus.com/product-users/by-external-id?app_id=app_123&external_user_id=usr_sara_101" \
  -H "Authorization: Bearer zrv_svc_your_service_key"
```

</CodeGroup>

<Callout type="tip" title="Grant credits only when needed">
  Inline inference creates the product user. Call `grantCreditByExternalId` only when your application adds a trial, subscription, promotional, or support balance.
</Callout>

## Identifier resolution

Use one of these identifiers:

1. `metadata.external_user_id` is your application's stable customer ID and the preferred integration field.
2. `metadata.product_end_user_id` is the internal Zorveus ID returned by the Management API.

The gateway does not use the OpenAI top-level `user` field as an `external_user_id` fallback.

---

## Verify the product user

After making the request:
1. Go to [app.zorveus.com](https://app.zorveus.com) -> **Product Users**.
2. Search for `usr_sara_101` or `Sara Connor`.
3. View the customer's:
   - Lifetime token consumption and requests
   - Remaining credit balance (if credit grants are applied)
   - Spending caps
   - Attributed usage records
