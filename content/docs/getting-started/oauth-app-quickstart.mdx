Build a tool whose users authorize AI usage against their own Zorveus funding account. If your organization pays for customer usage, use the [Business quickstart](/getting-started/startup-quickstart)

## Register the app and choose a client type

Create a Developer organization in the [dashboard](https://app.zorveus.com), then register an OAuth app. Add the exact callback URL for each environment, permitted scopes, and model access. Include `inference:write` and a model scope such as `models:*`

Use a confidential client when your backend exchanges and stores tokens. Keep its client secret on the server. Use a public client for browser-only or installed applications that cannot protect a secret. Public clients omit `client_secret` and still use PKCE

While the app is not public, use an owning organization member or an allowed [test user](/oauth/testing-draft-apps). The authorizing user needs a funding organization and sufficient wallet funds or eligible BYOK credentials

## Start authorization

Generate a fresh verifier, S256 challenge, and state for each attempt. Bind the verifier and state to the initiating local user session with an expiry. Send the browser to the authorization URL

The following TypeScript example is for a public browser client using `@zorveus/sdk`. Register `http://localhost:3000/oauth/callback` exactly for this local example

```bash
npm install @zorveus/sdk
```

```typescript
import { ZorveusOAuth } from "@zorveus/sdk";

export async function connectWallet(clientId: string) {
	const pkce = await ZorveusOAuth.generatePKCE();
	sessionStorage.setItem("zorveus_oauth_attempt", JSON.stringify({
		state: pkce.state,
		verifier: pkce.codeVerifier,
		expiresAt: Date.now() + 10 * 60 * 1000,
	}));

	window.location.assign(ZorveusOAuth.getAuthorizationUrl({
		clientId,
		redirectUri: "http://localhost:3000/oauth/callback",
		state: pkce.state,
		codeChallenge: pkce.codeChallenge,
		scopes: ["inference:write", "models:*"],
		baseURL: "https://app.zorveus.com",
	}));
}
```

The browser opens Zorveus sign-in and consent. The user selects a funding organization, reviews model access and spending policy, then approves or declines. Choose narrower model scopes in production when your app does not need the full catalog

For a backend client, generate and store the same values in a protected server session instead of `sessionStorage`. See [Authorization request](/oauth/authorization-request) for the HTTP parameters

## Handle the callback and exchange the code

On your callback route, require the saved attempt, check its expiry, and compare the returned state before processing success or denial. Consume the local attempt once

```typescript
import { ZorveusOAuth, Zorveus } from "@zorveus/sdk";

export async function finishWalletConnect(clientId: string) {
	const stored = sessionStorage.getItem("zorveus_oauth_attempt");
	sessionStorage.removeItem("zorveus_oauth_attempt");
	if (!stored) throw new Error("No pending wallet connection");

	const attempt = JSON.parse(stored) as {
		state: string; verifier: string; expiresAt: number;
	};
	const callbackUrl = new URL(window.location.href);
	window.history.replaceState(null, "", callbackUrl.pathname);
	if (Date.now() > attempt.expiresAt || callbackUrl.searchParams.get("state") !== attempt.state) {
		throw new Error("Wallet connection expired or state did not match");
	}

	const callback = ZorveusOAuth.validateCallback({
		urlOrParams: callbackUrl.searchParams,
		expectedState: attempt.state,
	});
	if (!callback.valid || !callback.code) {
		throw new Error(callback.errorDescription ?? callback.error ?? "Wallet connection failed");
	}

	const token = await ZorveusOAuth.exchangeToken({
		clientId,
		code: callback.code,
		codeVerifier: attempt.verifier,
		redirectUri: "http://localhost:3000/oauth/callback",
	});
	return new Zorveus({ apiKey: token.access_token });
}
```

Keep the returned client in application memory. For persistent connections, exchange and store the token on your backend against the local user's account. Do not put a confidential client's secret in a browser bundle

A backend exchange uses `POST https://api.zorveus.com/oauth/token` with a form-encoded body. It includes `grant_type=authorization_code`, `client_id`, `code`, `code_verifier`, and the exact `redirect_uri`. Confidential clients also include `client_secret`. See [Token exchange](/oauth/token-exchange)

## Send a request with the user's token

Use the returned client for this user only. Choose an authorized chat model through [model discovery](/inference/model-discovery)

```typescript
const response = await connectedClient.chat.completions.create({
	model: selectedChatModelId,
	messages: [{ role: "user", content: "Write a one-sentence welcome message." }],
});

console.log(response.choices[0].message.content);
```

A successful request returns a completion funded by the authorized connection. Do not silently fall back to your Business key if that token fails. User OAuth connections do not use Business product-user credit grants or allowance anchors

## Use React components

For an existing React app, `@zorveus/react` wraps the public-client flow. Mount the provider around both your application and callback route. Render `OAuthCallbackHandler` on the registered callback route so popup and redirect results can be processed

```tsx
import {
	ZorveusProvider,
	ConnectWalletButton,
	OAuthCallbackHandler,
	useZorveusInference,
} from "@zorveus/react";

export function WalletProvider({ children }: { children: React.ReactNode }) {
	return (
		<ZorveusProvider
			clientId="YOUR_PUBLIC_CLIENT_ID"
			redirectUri="http://localhost:3000/oauth/callback"
		>
			{children}
		</ZorveusProvider>
	);
}

export function ConnectButton() {
	return <ConnectWalletButton>Connect Zorveus wallet</ConnectWalletButton>;
}

export function WalletCallback() {
	return <OAuthCallbackHandler redirectTo="/" />;
}

export function Chat({ modelId }: { modelId: string }) {
	const { messages, submitPrompt, isStreaming, error } = useZorveusInference({ model: modelId });
	return (
		<div>
			<button disabled={isStreaming} onClick={() => void submitPrompt("Hello")}>
				Send
			</button>
			{error && <p role="alert">{error.message}</p>}
			<pre>{JSON.stringify(messages, null, 2)}</pre>
		</div>
	);
}
```

Install with `npm install @zorveus/react @zorveus/sdk`. In a framework with server components, place this code in a client component. Render the chat after the user connects. The provider accepts `clientId` and `redirectUri`, while the inference hook takes a `model` and returns conversation state and `submitPrompt`

## Disconnect and reconnect

Call [revocation](/oauth/revocation) when the user disconnects, then remove the local token after a confirmed result. Track uncertain network outcomes rather than claiming remote revocation succeeded

`expires_in` can be null. Honor it when present, handle revoked or invalid tokens, and use [reauthorization](/oauth/reauthorization) to replace tokens or change consent. There is no refresh-token flow
