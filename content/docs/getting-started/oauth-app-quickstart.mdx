With Zorveus, users can connect their account to your app and pay for their own AI requests. They sign in, choose the account that pays, and approve access. Your app then receives a token, which it uses to make requests for that user.

## 1. Register your app

Create a **Developer organization** in the [dashboard](https://app.zorveus.com), then register an OAuth app with these settings:

- **Client type:** `public` for React or browser TypeScript, `confidential` for the Python example. <InfoTooltip label="Client type">A public client runs in the browser without a client secret. A confidential client exchanges tokens on your server and keeps its secret there.</InfoTooltip>
- **Callback URL:** `http://localhost:3000/oauth/callback`. <InfoTooltip label="Callback URL">This is the page users return to after approving or declining access. The URL in your code must exactly match the one registered here.</InfoTooltip>
- **Permissions:** `inference:write` and `models:*`. <InfoTooltip label="Permissions">These let your app send AI requests and request access to models. For production, request only the model scopes your app needs.</InfoTooltip>

Enable the models your app needs and copy its **Client ID**. Use it in your chosen example below.

While the app is in draft, connect with an organization member or an added [test user](/oauth/testing-draft-apps). That user needs funds or eligible provider keys in the account they choose to pay from.

## 2. Get the user's token

The user clicks your connect button, signs in to Zorveus, and approves model access and spending limits. After they return to your callback page, exchange the approval code for their token.

Choose the implementation for your app. React and TypeScript run in the browser; Python runs on your server.

Install the React components:

```bash
npm install @zorveus/react @zorveus/sdk
```

Replace `YOUR_PUBLIC_CLIENT_ID` with your Client ID. Wrap your app and callback route with `WalletProvider`. Add `ConnectButton` where users connect, and render `WalletCallback` at `/oauth/callback`. The components handle the connection checks and token exchange.

```tsx
'use client';

import {
	ZorveusProvider,
	ConnectWalletButton,
	OAuthCallbackHandler,
} from "@zorveus/react";

export function WalletProvider({ children }: { children: React.ReactNode }) {
	return (
		<ZorveusProvider
			clientId="YOUR_PUBLIC_CLIENT_ID"
			redirectUri="http://localhost:3000/oauth/callback"
		>
			{children}
		</ZorveusProvider>
	);
}

export function ConnectButton() {
	return <ConnectWalletButton>Connect Zorveus</ConnectWalletButton>;
}

export function WalletCallback() {
	return <OAuthCallbackHandler redirectTo="/" />;
}
```

After the user connects, read `accessToken` inside a component wrapped by `WalletProvider`:

```tsx
import { useZorveusAuth } from "@zorveus/react";

// Inside your connected component:
const { accessToken } = useZorveusAuth();
```

Once `accessToken` is available, pass it to either SDK in step 3. The React provider keeps it in memory for the connected user.

Install the SDK:

```bash
npm install @zorveus/sdk
```

Call `connectWallet(clientId)` when the user clicks your connect button. The SDK generates the PKCE values used below. <InfoTooltip label="PKCE">PKCE links the returned authorization code to the browser that started the connection. Keep the verifier and state checks in the callback code.</InfoTooltip>

```typescript
import { ZorveusOAuth } from "@zorveus/sdk";

export async function connectWallet(clientId: string) {
	const pkce = await ZorveusOAuth.generatePKCE();
	sessionStorage.setItem("zorveus_oauth_attempt", JSON.stringify({
		state: pkce.state,
		verifier: pkce.codeVerifier,
		expiresAt: Date.now() + 10 * 60 * 1000,
	}));

	window.location.assign(ZorveusOAuth.getAuthorizationUrl({
		clientId,
		redirectUri: "http://localhost:3000/oauth/callback",
		state: pkce.state,
		codeChallenge: pkce.codeChallenge,
		scopes: ["inference:write", "models:*"],
		baseURL: "https://app.zorveus.com",
	}));
}
```

On `/oauth/callback`, add this function to check the returned connection and get the user's token. It checks that the attempt is still valid and uses it only once.

```typescript
import { ZorveusOAuth } from "@zorveus/sdk";

export async function finishWalletConnect(clientId: string) {
	const stored = sessionStorage.getItem("zorveus_oauth_attempt");
	sessionStorage.removeItem("zorveus_oauth_attempt");
	if (!stored) throw new Error("No pending wallet connection");

	const attempt = JSON.parse(stored) as {
		state: string; verifier: string; expiresAt: number;
	};
	const callbackUrl = new URL(window.location.href);
	window.history.replaceState(null, "", callbackUrl.pathname);
	if (Date.now() > attempt.expiresAt || callbackUrl.searchParams.get("state") !== attempt.state) {
		throw new Error("Wallet connection expired or state did not match");
	}

	const callback = ZorveusOAuth.validateCallback({
		urlOrParams: callbackUrl.searchParams,
		expectedState: attempt.state,
	});
	if (!callback.valid || !callback.code) {
		throw new Error(callback.errorDescription ?? callback.error ?? "Wallet connection failed");
	}

	const token = await ZorveusOAuth.exchangeToken({
		clientId,
		code: callback.code,
		codeVerifier: attempt.verifier,
		redirectUri: "http://localhost:3000/oauth/callback",
	});
	return token;
}
```

On the callback page, call it once to get the token:

```typescript
const token = await finishWalletConnect("YOUR_PUBLIC_CLIENT_ID");
const accessToken = token.access_token;
```

Keep this token response in memory for the connected user. It also includes `expires_in`, which tells you when they need to reconnect if an expiry is set.

Save your Client ID and Client Secret as `ZORVEUS_CLIENT_ID` and `ZORVEUS_CLIENT_SECRET` on your server.

Pass the signed-in user's server-side session to the helpers below. <InfoTooltip label="Server-side session">This stores data for the signed-in user on your server. Keep the verifier, client secret, and access token out of browser cookies and browser storage.</InfoTooltip>

When the user clicks your connect button, call `start_wallet_connect` and redirect their browser to the returned URL.

```python
import os
import time
from zorveus import ZorveusOAuth

CLIENT_ID = os.environ["ZORVEUS_CLIENT_ID"]
CLIENT_SECRET = os.environ["ZORVEUS_CLIENT_SECRET"]
REDIRECT_URI = "http://localhost:3000/oauth/callback"


def start_wallet_connect(server_session):
	pkce = ZorveusOAuth.generate_pkce()
	server_session["zorveus_oauth_attempt"] = {
		"state": pkce.state,
		"verifier": pkce.code_verifier,
		"expires_at": time.time() + 10 * 60,
	}
	return ZorveusOAuth.get_authorization_url(
		client_id=CLIENT_ID,
		redirect_uri=REDIRECT_URI,
		state=pkce.state,
		code_challenge=pkce.code_challenge,
		scopes=["inference:write", "models:*"],
		base_url="https://app.zorveus.com",
	)
```

On `/oauth/callback`, pass the full callback URL and the same user's session to `finish_wallet_connect`. It checks the connection attempt and returns the user's token response.

```python
def finish_wallet_connect(callback_url, server_session):
	attempt = server_session.pop("zorveus_oauth_attempt", None)
	if not attempt or time.time() > attempt["expires_at"]:
		raise ValueError("Connection attempt expired. Connect again.")

	callback = ZorveusOAuth.validate_callback(
		callback_url, expected_state=attempt["state"],
	)
	if not callback.valid or not callback.code:
		raise ValueError(callback.error_description or "Connection was not approved.")

	token = ZorveusOAuth.exchange_token(
		client_id=CLIENT_ID,
		client_secret=CLIENT_SECRET,
		code=callback.code,
		code_verifier=attempt["verifier"],
		redirect_uri=REDIRECT_URI,
	)
	return token
```

Call it once from your callback route:

```python
token = finish_wallet_connect(callback_url, server_session)
access_token = token.access_token
```

Keep the token and its expiry with the signed-in user's server-side session. Pass `access_token` to either SDK below when making requests for that user.

## 3. Use the token to make an AI request

The returned `access_token` works as an API key for the user's approved Zorveus connection. Pass it as `apiKey` or `api_key` when creating a client. Getting the token does not make an AI request.

Use `accessToken` from the React or TypeScript example, or `access_token` from Python. Choose a model through [model discovery](/inference/model-discovery) and set `selectedChatModelId` or `selected_chat_model_id` to its ID.

<ClientTabs items={["Zorveus SDK", "OpenAI SDK"]}>
<ClientTab value="Zorveus SDK">

<CodeGroup titles={["TypeScript", "Python"]}>

```typescript
import { Zorveus } from "@zorveus/sdk";

const client = new Zorveus({ apiKey: accessToken });

const response = await client.chat.completions.create({
	model: selectedChatModelId,
	messages: [{ role: "user", content: "Write a one-sentence welcome message." }],
});

console.log(response.choices[0].message.content);
```

```python
from zorveus import Zorveus

client = Zorveus(api_key=access_token)
try:
	response = client.chat.completions.create(
		model=selected_chat_model_id,
		messages=[{"role": "user", "content": "Write a one-sentence welcome message."}],
	)
	print(response.choices[0].message.content)
finally:
	client.close()
```

```python
from openai import OpenAI
```

The response is funded by the account the user approved. Use each user's token only for that user. If their connection fails, ask them to reconnect rather than charging your own API key.

## Next steps

- [Disconnect a user](/oauth/revocation): Revoke access before removing the saved token.
- [Reconnect a user](/oauth/reauthorization): Replace a revoked token or change the approved account, models, or limits.
- [Register a backend app](/oauth/register-an-app): Use a confidential client when your server manages tokens. Keep its client secret on the server.

Honor `expires_in` when present. Zorveus does not issue refresh tokens, so users reconnect when their token expires.
