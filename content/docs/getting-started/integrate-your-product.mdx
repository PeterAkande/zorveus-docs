title: Manage customer AI usage
description: Give customers an AI allowance, track their requests, and show their remaining balance. Connect paid plans or purchases when you need them.

Control how much AI each customer can use in your product. Give them a free allowance, include AI in a paid plan, or let them buy extra credits. Zorveus tracks their usage and checks their remaining allowance on each request.

Start with one allowance for all customers. Each customer gets their own balance, so one customer's spending does not reduce another's.

Follow [Make your first API request](/getting-started/startup-quickstart) if you need an app, an API key, or a funded route. Your product funds these model requests. Setting a customer allowance does not add money to your Zorveus wallet.

## 1. Set a customer allowance

In the [dashboard](https://app.zorveus.com), open your inference key's settings.

For this example, give each customer a $2 monthly allowance:

- Set **Cap amount** to `$2` and **Period** to `monthly`. <InfoTooltip label="Cap amount and period">Each customer gets their own $2 allowance every month.</InfoTooltip>
- Set **Credit mode** to `enforce`. <InfoTooltip label="Credit mode">Zorveus checks the customer's remaining allowance when their ID is included on a request.</InfoTooltip>
- Set **Overrun policy** to `limit_output`. <InfoTooltip label="Overrun policy">Zorveus can lower supported response lengths to fit the remaining allowance. It can reject requests that cannot fit or whose output cannot be limited.</InfoTooltip>

Keep this key on your backend as `ZORVEUS_API_KEY`. You can offer the allowance for free; no subscription or payment integration is required.

See [Set customer limits](/startups/configure-product-user-allowances) for other amounts, periods, and enforcement options.

## 2. Send requests with the customer's ID

Get the customer ID from your backend's signed-in user session and include it on each model request. Use the same ID for that customer every time.

Install `openai` with `npm install openai` for TypeScript or `pip install openai` for Python. Choose a chat model [available to your key](/inference/model-discovery). These examples use `openai/gpt-4.1-mini`.

<CodeGroup titles={["TypeScript (OpenAI SDK)", "Python (OpenAI SDK)", "cURL"]}>

```typescript
import OpenAI from "openai";

const client = new OpenAI({
	apiKey: process.env.ZORVEUS_API_KEY!,
	baseURL: "https://api.zorveus.com/v1",
});

export async function runChatRequest(customerId: string, prompt: string) {
	const response = await client.chat.completions.create(
		{
			model: "openai/gpt-4.1-mini",
			messages: [{ role: "user", content: prompt }],
		},
		{ headers: { "X-Zorveus-External-User-ID": customerId } },
	);

	return response.choices[0].message.content;
}

console.log(await runChatRequest("customer_42", "Say hello in five words."));
```

```python
import os
from openai import OpenAI


def run_chat_request(customer_id: str, prompt: str):
	with OpenAI(
		api_key=os.environ["ZORVEUS_API_KEY"],
		base_url="https://api.zorveus.com/v1",
	) as client:
		response = client.chat.completions.create(
			model="openai/gpt-4.1-mini",
			messages=[{"role": "user", "content": prompt}],
			extra_headers={"X-Zorveus-External-User-ID": customer_id},
		)
		return response.choices[0].message.content


print(run_chat_request("customer_42", "Say hello in five words."))
```

```bash
curl --fail-with-body https://api.zorveus.com/v1/chat/completions \
	-H "Authorization: Bearer $ZORVEUS_API_KEY" \
	-H "Content-Type: application/json" \
	-H "X-Zorveus-External-User-ID: customer_42" \
	-d '{
		"model": "openai/gpt-4.1-mini",
		"messages": [{"role": "user", "content": "Say hello in five words."}]
	}'
```

</CodeGroup>

Replace `customer_42` with the signed-in customer's ID. Run this code on your server. In an async Python handler, use an async client and await its requests.

The first request creates the customer's record in Zorveus. Later requests with the same ID count toward the same customer's allowance. The SDK examples print the response text; cURL returns the full response.

You do not need to check the balance before every request. Zorveus checks it when the request arrives. See [Track requests by customer](/inference/product-user-metadata) for optional profile details and activity labels.

## 3. Show the remaining balance

Create a [service key](/startups/service-keys) with `product_users:read` permission. Save it as `ZORVEUS_SERVICE_KEY` and your app ID as `ZORVEUS_APP_ID`. The service key reads customer data; `ZORVEUS_API_KEY` makes model requests. Keep both on your server.

Install `@zorveus/sdk` with `npm install @zorveus/sdk` for TypeScript or `zorveus` with `pip install zorveus` for Python.

Pass the same inference key when reading the balance so Zorveus knows which allowance settings to use. Opt-in creation also lets you show the starting balance before the customer's first AI request.

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "Python (zorveus)"]}>

```typescript
import { ZorveusServiceClient } from "@zorveus/sdk";

const service = new ZorveusServiceClient({
	apiKey: process.env.ZORVEUS_SERVICE_KEY!,
});

const user = await service.productUsers.getByExternalId({
	appId: process.env.ZORVEUS_APP_ID!,
	externalUserId: "customer_42",
	inferenceKey: process.env.ZORVEUS_API_KEY!,
	upsertIfMissing: true,
});

const available = user.allowance?.available_allowance ?? null;
console.log(available === null ? "Balance unavailable" : `$${available} remaining`);
console.log("Resets at:", user.allowance?.period_end ?? null);
```

```python
import os
from zorveus import ZorveusServiceClient

service = ZorveusServiceClient(api_key=os.environ["ZORVEUS_SERVICE_KEY"])
try:
	user = service.product_users.get_by_external_id(
		app_id=os.environ["ZORVEUS_APP_ID"],
		external_user_id="customer_42",
		inference_key=os.environ["ZORVEUS_API_KEY"],
		upsert_if_missing=True,
	)

	available = user.allowance.available_allowance if user.allowance else None
	print("Balance unavailable" if available is None else f"${available} remaining")
	print("Resets at:", user.allowance.period_end if user.allowance else None)
finally:
	service.close()
```

</CodeGroup>

A new customer with no usage or extra credits starts with $2. After a model request, the balance reflects their usage and any active reservations.

Use `allowance.available_allowance` for the total remaining amount, including usable extra credits, and `allowance.period_end` for the reset date. Keep amounts as decimal strings. If allowance data is missing, show "Balance unavailable" rather than treating the balance as zero.

Refresh the balance after AI requests or credit purchases. A positive balance does not guarantee the next request will fit, and it does not override a blocked customer status. See [Show a customer's balance](/startups/check-allowance) for the full behavior.

## Use credits in your product

You can show customers "200 credits left" instead of "$2 remaining." Zorveus keeps the underlying allowance in USD and returns the balance in your chosen credit units.

Set `app.creditUnitsPerUsd` to `"100"` in your [CLI manifest](/cli/manifest) and [apply the change](/cli/quickstart). Each $1 then equals 100 credits, so the $2 monthly allowance above gives each customer 200 credits.

Display `allowance.remaining_credit_units` from the balance read above. Zorveus updates the balance as customers use AI; your app does not need a separate credit ledger. If the field is missing, show "Balance unavailable."

Credits work with free allowances and paid plans. See [Show a customer's balance](/startups/check-allowance#show-the-balance-in-credits) for the UI code or [Write Room](/code-labs/write-room-saas) for a working app. You can also [set a rate on an individual grant](/startups/credit-grants#choose-a-conversion-rate).

## When a request is rejected

Inspect the structured Zorveus error code as well as the HTTP status. A `403` can mean several different things:

| Error | What your app should do |
| --- | --- |
| `zorveus_product_user_allowance_insufficient` | Explain that this request exceeds the customer's remaining allowance. They can try a smaller request, wait for a reset, or use an extra allowance option your product offers. |
| `zorveus_reservation_insufficient_balance` | Ask your product's operator to fund the Zorveus wallet. This is separate from the customer's allowance. |
| `zorveus_model_not_allowed` | Use a model allowed by the key's settings. Buying extra credits does not resolve model access. |

The gateway can nest the Zorveus code inside `error.provider_specific_fields.error`. Follow [Error handling](/platform/errors) for the response shapes and other failures.

## Optional: connect paid plans or credit purchases

You can add payment features when your product needs them. Your payment provider handles the money; Zorveus tracks the AI allowance you assign to each customer.

### Include AI in a paid plan

For example, a $5 subscription can include the same $2 monthly allowance used above. If customers on another plan need a different allowance, set up an inference key with that plan's allowance settings.

Your backend selects the key for the customer's subscription in your database. Keep their customer ID stable across plan changes and use the selected key for both AI requests and balance reads. Setting `plan: "pro"` in profile metadata does not authorize a plan.

<FlowDiagram flow="plan-keys" />

See [One key for multiple plans](/startups/routing-keys) for selecting a plan with an alias. For [prorated upgrades](/startups/prorated-plan-changes), apply the plan change before reading the balance with the new key.

### Sell extra AI allowance

A customer could pay $5 for $3 of extra allowance. After your backend verifies the payment and looks up the purchase, use a service key with `product_users:write` permission to grant that allowance.

Keep one reference for the purchase. Retrying with the same reference and grant details returns the original grant instead of adding credits twice. Changed details under that reference return a conflict.

Follow [Grant customer credits](/startups/credit-grants) for welcome bonuses, support adjustments, and verified purchases. The [payment example](/startups/credit-grants#grant-credits-after-a-payment) shows how to connect your payment provider.
