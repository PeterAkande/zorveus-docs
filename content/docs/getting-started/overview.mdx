## Choose your integration mode

| Goal | Integration Mode | Funding Source | Key Credential |
| :--- | :--- | :--- | :--- |
| **Direct model access** | [API Quickstart](/getting-started/startup-quickstart) | Business wallet or [BYOK](/startups/provider-credentials) | API Key (`zrv_...`) |
| **SaaS customer billing** | [Integrate your product](/getting-started/integrate-your-product) | Business wallet or [BYOK](/startups/provider-credentials) | API Key (`zrv_...`) + Service Key (`zrv_svc_...`) |
| **End-user funds third-party app** | [OAuth App Quickstart](/getting-started/oauth-app-quickstart) | User's Personal/Company wallet | Scoped OAuth Token (`zrv_...`) |

<Callout type="info" title="Need an API key? Choose a Business Organization">
  If you want an API key (`zrv_...`) to call models from your code, server backend, or scripts, select or create a **Business Organization** in the dashboard. Even if you are a solo developer building an independent project or just need model access, Business is the workspace that funds AI and mints API keys. A **Developer Organization** only registers third-party OAuth applications where end-users bring their own wallets
</Callout>

## Credential terminology

Understanding credential types ensures you use the correct secret in each context:

- **API Key (`zrv_...`)**: Secret token used in `Authorization: Bearer zrv_...` against the model gateway (`https://api.zorveus.com/v1` or native wire endpoints). Used to execute model inference and inspect connection spend. Shown only once upon creation.
- **Service Key (`zrv_svc_...`)**: Server-to-server credential for supported `/product-users/by-external-id` operations at `https://api.zorveus.com`; never expose this key in browser code and do not pass it to inference endpoints.
- **Client ID & Client Secret (`zrv_client_...` / `zrv_client_secret_...`)**: Credentials for registered OAuth applications to authenticate during PKCE token exchanges.
- **Provider Credential**: Encrypted upstream API keys (e.g. OpenAI, Anthropic, Gemini) stored in Zorveus for Bring your own Key (BYOK) routing

<Callout type="warning" title="Security Boundary">
  Never use a **Service Key** (`zrv_svc_...`) for model inference requests or inside frontend client bundles. Use service keys for customer reads, upserts, credit grants, and allowance debt. See [Service clients](/startups/service-keys) for scopes and SDK actions. Configure connections, caps, and BYOK credentials in the dashboard. Model inference requires an **API Key** (`zrv_...`)
</Callout>

## Production endpoints

Always use production endpoints in deployed applications:

```text
Inference Base URL:  https://api.zorveus.com/v1
Management Base URL: https://api.zorveus.com
OAuth Authorize URL: https://app.zorveus.com/oauth/authorize
```

## Available SDKs and packages

Zorveus works with standard OpenAI and Anthropic SDKs, plus dedicated Zorveus adapters and React OAuth components:

| Client | Install | Best for |
| --- | --- | --- |
| OpenAI Python or TypeScript | `pip install openai` or `npm install openai` | Direct chat, embeddings, images, and audio completions |
| Zorveus Python | `pip install zorveus` | Server-side product user allowances and credit grants |
| Zorveus TypeScript | `npm install @zorveus/sdk` | Server-side product user allowances, credits, and usage |
| OpenAI adapters | `pip install 'zorveus[openai]'` or `npm install @zorveus/sdk openai` | Typed attribution helpers around OpenAI clients |
| Vercel AI SDK adapter | `npm install @zorveus/sdk ai @ai-sdk/openai` | Next.js streaming UIs and `streamText` routes |
| React OAuth components | `npm install @zorveus/react @zorveus/sdk` | Client-side OAuth login buttons for user-funded apps |
