Build a backend that sends a model request and records the usage against one of your customers. Your organization pays through its Zorveus wallet or a connected provider account

## Create your credentials

In the [dashboard](https://app.zorveus.com), select or create a **Business** organization. Use Business even for a solo project. A Developer organization is for registering OAuth apps where users bring their own funding

Fund the wallet, or follow the [BYOK quickstart](/getting-started/byok-quickstart). Create an app, then create an inference API key in its connection settings. Save the app ID and store the `zrv_...` key on your server. The full secret is shown only when created or rotated

For a customer allowance, configure a daily or monthly connection cap and use `enforce`. For example, a $10 monthly cap gives each attributed product user a $10 base allowance. Your server must still attach a customer ID on every customer request. See [Configure product-user allowances](/startups/configure-product-user-allowances)

## Find a model your key can use

Set your key in a local shell or your application's secret store:

```bash
export ZORVEUS_API_KEY='zrv_your_api_key'

curl --fail-with-body https://api.zorveus.com/v1/models \
	-H "Authorization: Bearer $ZORVEUS_API_KEY"
```

The response contains `data`, an array of model objects. Copy a chat model's `id` into `ZORVEUS_MODEL`. Use [the model catalog](https://www.zorveus.com/models) to check its task support. An embedding or audio model cannot serve a chat request just because it appears in the list

```bash
export ZORVEUS_MODEL='YOUR_CHAT_MODEL_ID'
```

If the list is empty, check the key's allowed models in the dashboard. A wildcard such as `openai/*` is a policy, not a model ID

## Send the first request

These examples run on your server. Install the package for the tab you use with `pip install openai` or `npm install openai`

<CodeGroup titles={["cURL", "Python (OpenAI SDK)", "TypeScript (OpenAI SDK)"]}>

```bash
curl --fail-with-body https://api.zorveus.com/v1/chat/completions \
	-H "Authorization: Bearer $ZORVEUS_API_KEY" \
	-H "Content-Type: application/json" \
	-H "X-Zorveus-External-User-ID: customer_42" \
	-d "$(jq -n --arg model "$ZORVEUS_MODEL" '{model: $model, messages: [{role: "user", content: "Write a one-sentence welcome message."}]}')"
```

```python
import os
from openai import OpenAI

with OpenAI(
	api_key=os.environ["ZORVEUS_API_KEY"],
	base_url="https://api.zorveus.com/v1",
) as client:
	response = client.chat.completions.create(
		model=os.environ["ZORVEUS_MODEL"],
		messages=[{"role": "user", "content": "Write a one-sentence welcome message."}],
		extra_headers={"X-Zorveus-External-User-ID": "customer_42"},
	)
	print(response.choices[0].message.content)
```

```typescript
import OpenAI from "openai";

const client = new OpenAI({
	apiKey: process.env.ZORVEUS_API_KEY,
	baseURL: "https://api.zorveus.com/v1",
});

const response = await client.chat.completions.create(
	{
		model: process.env.ZORVEUS_MODEL!,
		messages: [{ role: "user", content: "Write a one-sentence welcome message." }],
	},
	{ headers: { "X-Zorveus-External-User-ID": "customer_42" } },
);

console.log(response.choices[0].message.content);
```

</CodeGroup>

The cURL example uses `jq` to build JSON. Replace `customer_42` with the ID from your authenticated application user when integrating this into your backend

A successful request returns HTTP `200` with generated text in `choices[0].message.content`. In the dashboard, the app's product users include `customer_42` and its usage. You do not need to create a product user before the first request

## Check the result and handle a rejection

A `401` means the inference key needs attention. A wallet shortfall returns `402`. An enforced allowance or model-policy rejection returns `403`. Read the structured Zorveus code as described in [Error handling](/platform/errors). Do not label every `403` as exhausted customer credits

To read this customer's allowance from your backend, create a [service key](/startups/service-keys) with `product_users:read` and follow the [product-user quickstart](/getting-started/product-user-quickstart). The inference key and service key have different jobs

## Add your product's policies

For multiple subscription plans, configure separate plan connections and group their keys under [one routing key](/startups/routing-keys). Select the plan from trusted backend data and keep the same external user ID when a customer changes plans

Continue with [Integrate your product](/getting-started/integrate-your-product) for the production workflow, [credit grants](/startups/credit-grants) for extra allowance, or [OAuth](/getting-started/oauth-app-quickstart) when users should fund requests from their own accounts
