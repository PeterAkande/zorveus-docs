Open **Usage** in the [Zorveus dashboard](https://app.zorveus.com) to inspect model requests, token volume, prompt cache savings, and costs across your organization.

---

## Filter and find a request

Use the filters at the top of **Usage** to narrow down traffic or track down a specific call:

- **Date range**: Choose a preset (Today, Last 7 Days, Month to Date) or a custom range.
- **Application and API key**: Isolate one app or API key, or view organization-wide traffic.
- **Model and provider**: Group by provider (OpenAI, Anthropic, Google) or filter to one model.
- **Billing mode**: Separate `wallet` calls from `byok` calls.
- **Product user**: Search by `external_user_id` or customer name to inspect one customer's history.

Keep the Zorveus request ID and reservation ID in your server logs when available so you can match an event quickly. For programmatic reads from your backend, use [Key usage](/api-reference/usage) for key-level totals or the [product-user API](/api-reference/product-users) for one customer's balance and activity.

## Usage events table

Below the summary charts, **Usage events** lists each completed request:

| Column | What it shows |
| :--- | :--- |
| **Timestamp** | UTC completion time. |
| **Model** | Resolved model ID (for example, `openai/gpt-4.1-mini` or `anthropic/claude-sonnet-5`). |
| **Input tokens** | Total input tokens. When prompt caching applies, cache reads appear directly under the total. |
| **Output tokens** | Generated output tokens. |
| **Usage cost** | Reference-priced spend counted against caps and customer credits. |
| **Billed to wallet** | Cash deducted from your organization wallet (`$0.00` for BYOK unless a platform fee applies). |
| **Mode** | `wallet` or `byok`. |
| **Status** | `succeeded`, `partially_settled`, or `failed`. |

## Prompt cache savings

When an upstream provider reports prompt caching, cache reads appear under total input in the events table:

```text
Input
10,000
7,000 cache read
```

Click any row to open the **Event details** drawer and view the **Input details** breakdown:

```text
Total input                         10,000
Normal input                         1,000
Cache read                           7,000
Cache creation, default duration     1,500
Cache creation, one hour               500
Output                               2,000
Service tier                      standard
AI allowance saved                 $0.0105
```

- **Normal input**: Uncached prompt tokens (total input minus cache reads and cache creations).
- **Cache read**: Prompt tokens served from cache at the provider's discounted rate.
- **Cache creation**: Prompt tokens written to cache for later requests.
- **AI allowance saved**: Reference-priced allowance saved compared to standard input pricing. On BYOK requests, this reflects virtual allowance saved rather than a discount on your upstream provider invoice.

## Understand the three cost figures

The **Event details** drawer separates three amounts so you never confuse customer allowance with cash billed to your wallet:

1. **Usage cost (`virtual_spend`)**: Reference-priced value counted against spending caps and customer credits. Calculated the same way for both wallet and BYOK calls.
2. **Billed to wallet (`sell_cost`)**: Actual amount charged to your Zorveus organization wallet.
3. **Provider cost (`provider_cost`)**: Wholesale cost reported for the upstream model provider.

If a request finished past its allowance under an overrun policy, the drawer also shows **Uncovered virtual spend** and the active **Overrun policy** (`limit_output`, `allow_overrun`, or `carry_overrun_forward`).

## Business activity metadata

Requests can attach [usage metadata](/inference/product-user-metadata#attach-business-context-to-usage-events) such as an activity ID, label, or conversation ID. Authorized usage-event responses return that object as `usage_metadata` (or `null` when none was sent), while callers without usage-detail permission see it redacted.

To list combined credit grants and AI usage for a customer from your backend, see [Product-user activity](/startups/product-user-activity).
