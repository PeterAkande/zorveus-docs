Service keys (`zrv_svc_...`) authenticate backend requests to `https://api.zorveus.com` for reading customer allowances, updating customer profiles, and granting credits. Keep service keys on your server. A service key cannot make AI model requests.

---

## Create a service key

1. Open your **Business** organization in the [Zorveus dashboard](https://app.zorveus.com) and go to **Service Keys**.
2. Click **Create Service Key** and select the scopes your backend needs.
3. Copy the secret (`zrv_svc_...`) and save it as `ZORVEUS_SERVICE_KEY` on your server. Also copy your app's ID from **Apps** (`ZORVEUS_APP_ID`).

### Choose scopes

| Scope | What it allows |
| :--- | :--- |
| `product_users:read` | Read a customer profile, remaining allowance, carried allowance debt, and credit grants. |
| `product_users:write` | Create or update a customer profile, set subscription anchors, and grant credits. Includes read permissions. |

Organizations, apps, API keys, caps, BYOK provider credentials, team access, webhooks, customer status changes, and credit-grant revocations are managed in the dashboard (or CLI where supported), not through service keys.

## Create the client

Install `@zorveus/sdk` for TypeScript or `zorveus` for Python:

<CodeGroup titles={["TypeScript", "Python"]}>

```bash
npm install @zorveus/sdk
```

```bash
pip install zorveus
```

</CodeGroup>

Initialize `ZorveusServiceClient` once and reuse it across your backend:

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "Python (zorveus)"]}>

```typescript
import { ZorveusServiceClient } from "@zorveus/sdk";

export const service = new ZorveusServiceClient({
  apiKey: process.env.ZORVEUS_SERVICE_KEY!,
});
```

```python
import os
from zorveus import ZorveusServiceClient

service = ZorveusServiceClient(api_key=os.environ["ZORVEUS_SERVICE_KEY"])
```

</CodeGroup>

- The client sends `Authorization: Bearer ...` to `https://api.zorveus.com` (without `/v1`). Set `baseURL` in TypeScript or `base_url` in Python only when targeting another environment.
- In Python, call `service.close()` on shutdown. For async handlers, use `AsyncZorveusServiceClient`, `await` its calls, and call `await service.close()` on shutdown.

## Example: upsert and read a customer

Upserting a customer returns a wrapper (`{ created, product_user }`), while reading by external ID returns the profile directly:

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "Python (zorveus)"]}>

```typescript
const appId = process.env.ZORVEUS_APP_ID!;

const result = await service.productUsers.createOrUpdate({
  appId,
  externalUserId: "customer_42",
  displayName: "Ada Lovelace",
});
console.log(result.created, result.product_user.external_user_id);

const profile = await service.productUsers.getByExternalId({
  appId,
  externalUserId: "customer_42",
});
console.log(profile.getTotalAvailableToSpend());
```

```python
import os

app_id = os.environ["ZORVEUS_APP_ID"]

result = service.product_users.create_or_update(
    app_id=app_id,
    external_user_id="customer_42",
    display_name="Ada Lovelace",
)
print(result.created, result.product_user.external_user_id)

profile = service.product_users.get_by_external_id(
    app_id=app_id,
    external_user_id="customer_42",
)
print(profile.get_total_available_to_spend())
```

</CodeGroup>

Replace `customer_42` with the signed-in customer's stable ID from your backend.

Reading an unknown customer returns HTTP `404` by default. To create the profile automatically during a read, send `X-Zorveus-Upsert-Product-User: true`; see [Create a missing user during a read](/api-reference/product-users#create-a-missing-user-during-a-read).

Credit grants change customer balances. Always pass a unique `external_reference` (such as the payment ID) instead of blindly retrying after an uncertain network error. See [Idempotency](/platform/idempotency).
