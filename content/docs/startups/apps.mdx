An **App** represents a product workspace in Zorveus that groups API keys, allowed model policies, spending caps, and usage metrics.

Whether you run an internal AI feature or build a public platform, Apps provide strict boundaries around who can issue requests and which models they can access.

---

## App Types

Zorveus supports two main app configurations:

| App Type | Primary Use Case | Authentication Method | Funding Source |
| :--- | :--- | :--- | :--- |
| **Internal Startup App** | Backend services funding AI for your own product users. | API Key (`zrv_...`) for inference, Service Key (`zrv_svc_...`) for management | Startup Organization Wallet |
| **Developer OAuth App** | Third-party client tools or plugins where users bring their wallets. | OAuth 2.0 PKCE (`zrv_client_...`) | User's Personal or Team Wallet |

---

## Model Allow lists & Security Policies

Each App configures an allowed models array. Requests specifying a model outside the allowlist are rejected with an HTTP `403 Forbidden` response.

```json
{
  "allowed_models": [
    "openai/gpt-4.1-mini",
    "anthropic/claude-3-5-haiku",
    "openrouter/deepseek/deepseek-r1"
  ]
}
```

### Supported Pattern Formats

- `*`: Grants access to all models available in the Zorveus catalog.
- `provider/*`: Grants access to all models under a specific provider namespace (e.g. `openai/*` or `anthropic/*`).
- `provider/model-name`: Restricts access to an explicit model identifier.

## Connection policies

Each App Connection contains execution policies that govern inference requests:

### 1. Credit enforcement mode (`credit_mode`)
- `enforce_if_present` (default): Enforces spending caps and product-user credits when a product user is supplied. Bypasses caps for internal requests without a product user.
- `enforce`: Strictly enforces caps on all requests.
- `track_only`: Records virtual spend and allocates base cap and credits without blocking.
- `disabled`: Bypasses cap checks and credits for benchmarking or analytics.

### 2. Allowance overrun policy (`overrun_policy`)
- `limit_output` (default): Automatically lowers the provider output token limit to the affordable budget.
- `allow_overrun`: Lets the request run to declared limits, recording any excess as uncovered virtual spend.
- `carry_overrun_forward`: Lets the request run to declared limits, recording excess as allowance debt repaid by future credits or cap resets.
