---
title: Inference API keys
description: Create, inspect, and rotate keys for server-side model requests.
---

An inference key, `zrv_...`, authenticates model requests under an app connection. The connection supplies model access, spending policy, credit mode, and overrun policy

## Create a key

Select a Business organization in the [dashboard](https://app.zorveus.com). Create an app and generate an API key in its connection settings. Copy the full secret when it is shown and keep it in your backend's secret store

Complete the [Business quickstart](/getting-started/startup-quickstart) for a first request. Configure [product-user allowances](/startups/configure-product-user-allowances) before serving customers. Send your trusted external customer ID on every customer request

For multiple plan policies, use [one routing key](/startups/routing-keys) to select among member inference keys with `X-Zorveus-Key-Alias`

## Inspect key usage

```bash
curl --fail-with-body https://api.zorveus.com/inference-keys/usage \
	-H "Authorization: Bearer $ZORVEUS_API_KEY"
```

The response includes `spend_cap`, `spent_this_period`, `remaining_balance`, and `reset_at`. Nullable values are described in [Key usage](/api-reference/usage). The TypeScript SDK calls this `client.getUsage()`, and the Python SDK calls it `client.get_usage()`

This is a key-level summary, not a customer's available allowance. Use [Check available allowance](/startups/check-allowance) for a product user

CORS support permits browser requests but does not protect an embedded key. Keep shared Business keys on your server. Browser OAuth apps use the user's scoped token

## Rotate a key

Create a replacement key for the same connection, deploy it to your backend, and verify a request before revoking the previous key in the dashboard. Connection policy stays with the connection

Use a [service key](/startups/service-keys) for supported product-user management. An inference key does not grant access to those endpoints
