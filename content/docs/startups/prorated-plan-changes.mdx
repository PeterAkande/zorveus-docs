---
title: Prorate plan upgrades
description: Prorate AI allowance increases when customers upgrade mid-cycle.
---

Give customers the remaining portion of an allowance increase when they upgrade. For example, upgrading from $2 to $10 halfway through the cycle adds $4 to the current cycle's allowance. The full $10 applies at the next reset.

Configure an active spending cap in each plan's inference key settings. Both caps must use the same period, such as monthly, and currency, such as USD.

---

## Understand the arithmetic

Consider a customer upgrading from Starter to Pro halfway through their monthly billing cycle:

- **Starter plan allowance**: $2.00 per month
- **Pro plan allowance**: $10.00 per month
- **Total increase**: $10.00 - $2.00 = $8.00

If the customer upgrades on June 16 in a June 1 to July 1 UTC cycle, exactly half of the cycle remains:

```text
Prorated increase     = $8.00 × 0.50 = $4.00
Adjusted cycle cap    = $2.00 + $4.00 = $6.00
Spendable balance     = $6.00 - $1.00 used = $5.00
```

The customer gets $5.00 of spendable allowance for the remainder of June. On July 1, the full $10.00 monthly Pro allowance takes effect.

## Set a default header for proration

Set `X-Zorveus-Allowance-Change-Policy: prorate_increase` once on your backend client for requests on the same plan and eligible upgrades. Your backend picks the inference key for the customer's current subscription. When the key points to a plan with a higher allowance, Zorveus detects the change and prorates the increase if both plans qualify.

The customer's first request establishes their starting plan. Later requests on the same plan keep the existing allowance cap. Use the same customer ID across plans and get it from your signed-in session.

Omit the header when switching to a plan with a lower or equal allowance, or with an incompatible period or currency. Zorveus rejects those plan changes with HTTP `400` if you send `prorate_increase`.

These examples use the Pro key after the customer upgrades from Starter. Use the same header configuration for both keys.

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "Python (zorveus)", "cURL"]}>

```typescript
import { Zorveus } from "@zorveus/sdk";

const client = new Zorveus({
  apiKey: process.env.ZORVEUS_PRO_KEY!,
  defaultHeaders: {
    "X-Zorveus-Allowance-Change-Policy": "prorate_increase",
  },
});

const response = await client.chat.completions.create({
  model: "anthropic/claude-3-5-sonnet",
  messages: [{ role: "user", content: "Analyze monthly report" }],
}, {
  headers: {
    "X-Zorveus-External-User-ID": "customer_42",
  },
});

console.log(response.choices[0].message.content);
```

```python
import os
from zorveus import Zorveus

client = Zorveus(
    api_key=os.environ["ZORVEUS_PRO_KEY"],
    default_headers={
        "X-Zorveus-Allowance-Change-Policy": "prorate_increase",
    },
)
try:
    response = client.chat.completions.create(
        model="anthropic/claude-3-5-sonnet",
        messages=[{"role": "user", "content": "Analyze monthly report"}],
        extra_headers={"X-Zorveus-External-User-ID": "customer_42"},
    )
    print(response.choices[0].message.content)
finally:
    client.close()
```

```bash
curl --fail-with-body https://api.zorveus.com/v1/chat/completions \
  -H "Authorization: Bearer $ZORVEUS_PRO_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Zorveus-External-User-ID: customer_42" \
  -H "X-Zorveus-Allowance-Change-Policy: prorate_increase" \
  -d '{
    "model": "anthropic/claude-3-5-sonnet",
    "messages": [{"role": "user", "content": "Analyze monthly report"}]
  }'
```

### Send the AI request before checking the Pro balance

When a customer moves from Starter to Pro, use the Pro inference key in this order:

1. Send the customer's next AI request with `prorate_increase`. Zorveus sees the move from Starter to Pro and prorates the increase.
2. Then use the Pro key to check their adjusted balance.

Checking the balance with the Pro key first saves Pro as the customer's last used plan. The next AI request then compares Pro with Pro, so Zorveus skips the Starter-to-Pro adjustment.

---

## Read the adjusted balance

After the upgrade request completes, read the customer profile from your backend using your service key:

```typescript
const user = await service.productUsers.getByExternalId({
  appId: process.env.ZORVEUS_APP_ID!,
  externalUserId: "customer_42",
  inferenceKey: process.env.ZORVEUS_PRO_KEY!,
});

console.log(`Adjusted allowance: $${user.allowance?.available_allowance}`); // "$5.000000000000"
console.log(`Resets at:          ${user.allowance?.period_end}`);
```

## Supported scope and restrictions

- Both plan keys must belong to the same app and have active daily or monthly allowances with matching periods and currencies.
- A limit set directly on the customer overrides the plan allowance and prevents proration.
- **Payment provider billing**: Your payment provider (such as Stripe) handles subscription fees and monetary invoice proration. Zorveus calculates the AI model allowance.
