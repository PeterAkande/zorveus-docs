Show customers their AI requests, credit purchases, and other credit changes in one history. Read the activity from your backend and display a label, amount, status, and date for each entry.

The service API returns AI usage and credit movements in one paginated feed, making it easy to build a customer billing and activity page in your application.

<ApiEndpoint method="GET" path="/product-users/by-external-id/activity" auth="service_key" />

---

## Load customer activity

Fetching customer activity requires a server-side [service key](/startups/service-keys) with `product_users:read` permission:

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "Python (zorveus)", "cURL"]}>

```typescript
import { ZorveusServiceClient } from "@zorveus/sdk";

const service = new ZorveusServiceClient({
  apiKey: process.env.ZORVEUS_SERVICE_KEY!,
});

const page = await service.productUsers.listActivityByExternalId({
  appId: process.env.ZORVEUS_APP_ID!,
  externalUserId: "customer_42",
  limit: 20,
});

for (const item of page.items) {
  console.log(`${item.created_at} | ${item.label} | $${item.amount} | ${item.status}`);
}
```

```python
import os
from zorveus import ZorveusServiceClient

service = ZorveusServiceClient(api_key=os.environ["ZORVEUS_SERVICE_KEY"])

page = service.product_users.list_activity_by_external_id(
    app_id=os.environ["ZORVEUS_APP_ID"],
    external_user_id="customer_42",
    limit=20,
)

for item in page.items:
    print(f"{item.created_at} | {item.label} | ${item.amount} | {item.status}")
```

```bash
curl --fail-with-body --get https://api.zorveus.com/product-users/by-external-id/activity \
  -H "Authorization: Bearer $ZORVEUS_SERVICE_KEY" \
  --data-urlencode "app_id=$ZORVEUS_APP_ID" \
  --data-urlencode "external_user_id=customer_42" \
  --data-urlencode "limit=20"
```

## Display each entry

In your customer-facing dashboard, display the item's label, amount, status, and date. These example credit quantities use 100 credits per $1:

| Date | Activity | Monetary amount | Credit units | Status |
| :--- | :--- | :--- | :--- | :--- |
| Nov 22, 10:14 UTC | **Drafting assistant** | -$0.0200 | 2 credits | Succeeded |
| Nov 21, 16:30 UTC | **Extra AI allowance purchase** | +$3.0000 | 300 credits | Completed |
| Nov 20, 09:00 UTC | **Customer support reply** | -$0.0150 | 1.5 credits | Succeeded |

### Field mappings

- **Label**: Uses the `activity_label` sent in `usage_metadata` (or the `X-Zorveus-Usage-Metadata` header). If no custom label was sent, Zorveus displays `"AI usage"`. Credit purchases use the grant's `reason`.
- **Amount**: Monetary usage is returned as a negative signed decimal string (e.g. `"-0.020000000000"`). Credit additions are positive.
- **Charged credit units**: When credit units are configured, usage rows include `charged_credit_units`. This is the exact quantity recorded at settlement. Use this saved field rather than recalculating past usage with current conversion rates. If null, display the monetary amount.
- **Status**: The outcome of the event (`succeeded`, `completed`, `failed`, etc.).

## Show credits used per request

If your UI shows credits instead of dollars, use `charged_credit_units` on usage entries. For example, `"2.000000000000"` means the request used 2 credits. Zorveus saves the quantity when it settles the request, so later conversion-rate changes do not rewrite past charges.

Use the activity page loaded above:

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "Python (zorveus)"]}>

```typescript
for (const item of page.items) {
	const amount = item.type === "usage" && item.charged_credit_units != null
		? `${item.charged_credit_units} credits used`
		: `${item.amount} ${item.currency}`;
	console.log(`${item.label}: ${amount}`);
}
```

```python
for item in page.items:
	if item.type == "usage" and item.charged_credit_units is not None:
		amount = f"{item.charged_credit_units} credits used"
	else:
		amount = f"{item.amount} {item.currency}"
	print(f"{item.label}: {amount}")
```

</CodeGroup>

Keep decimal precision when formatting credit units. If a usage entry has no saved credit quantity, show its monetary amount instead. Do not recalculate old charges using today's conversion rate.

Credit movements such as purchases do not include `charged_credit_units`. Use your saved purchase details to show "300 credits added," or display the returned monetary amount. For the current total balance, read [the customer's balance](/startups/check-allowance#show-the-balance-in-credits) rather than adding activity entries together.

## Load more results

The activity endpoint returns an opaque `next_cursor` when more records are available:

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "Python (zorveus)"]}>

```typescript
if (page.has_more && page.next_cursor) {
  const nextPage = await service.productUsers.listActivityByExternalId({
    appId: process.env.ZORVEUS_APP_ID!,
    externalUserId: "customer_42",
    limit: 20,
    cursor: page.next_cursor,
  });
}
```

```python
if page.has_more and page.next_cursor:
    next_page = service.product_users.list_activity_by_external_id(
        app_id=os.environ["ZORVEUS_APP_ID"],
        external_user_id="customer_42",
        limit=20,
        cursor=page.next_cursor,
    )
```

</CodeGroup>

Keep query filters identical when requesting subsequent cursor pages. Changing filters requires starting a new pagination sequence.

## Understand the charge breakdown

Each usage item includes a breakdown showing how the cost was covered:

```json
{
  "id": "ue_123",
  "type": "usage",
  "label": "Drafting assistant",
  "amount": "-0.020000000000",
  "currency": "USD",
  "status": "succeeded",
  "charged_credit_units": "2.000000000000",
  "base_allowance_charge_amount": "0.020000000000",
  "credit_charge_amount": "0.000000000000",
  "uncovered_charge_amount": "0.000000000000"
}
```

- `base_allowance_charge_amount`: The portion settled against the customer's recurring plan allowance.
- `credit_charge_amount`: The portion settled against extra purchased credits.
- `uncovered_charge_amount`: Excess spend permitted under an `allow_overrun` policy.
