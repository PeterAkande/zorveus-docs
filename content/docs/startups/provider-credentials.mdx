---
title: Provider keys (BYOK)
description: Add your own upstream provider API keys in the Zorveus dashboard with priority ordering, rotation, and optional wallet fallback.
---

With Bring Your Own Key (BYOK), you can connect your organization's own provider keys (such as OpenAI, Anthropic, or Google Gemini) in the [Zorveus dashboard](https://app.zorveus.com) under **Provider Credentials**.

Your app keeps sending model requests with your Zorveus API key (`zrv_...`), never the upstream provider secret. Zorveus decrypts and injects your matching provider key at request time while keeping customer allowances, spending limits, usage logs, and failover intact.

You can add multiple keys for the same provider and assign each key a different priority. See [Key priority, rotation, and fallback](/startups/automatic-routing) for how Zorveus orders keys and rotates around failures.

---

## Add a provider key

1. Open your organization in the [Zorveus dashboard](https://app.zorveus.com) and go to **Provider Credentials**.
2. Select a provider and enter the key or credentials requested by the form.
3. Set the allowed model policy (for example, `openai/*` or specific model IDs).
4. Choose a routing mode (`auto_resolve` or `manual_grant_only`) and set a **Routing priority** number if you have more than one key for that provider.
5. Save the credential and confirm it passes validation.

Zorveus validates credentials before storing them and never returns raw secrets after creation.

---

## Choose a routing mode

| Mode | Behavior |
| :--- | :--- |
| `auto_resolve` | Zorveus can automatically select this key for any API key in the organization whose request matches the credential's model policy. |
| `manual_grant_only` | Zorveus uses this key only for API keys that have an explicit grant to it. |
| `disabled` | Zorveus skips this key during routing. |

Adding a provider key does not bypass the allowed-model policy on an API key.

## Supported providers

The dashboard form shows the exact fields required for each provider enabled in your workspace:

| Provider | Provider ID | Typical model policy | Notes |
| :--- | :--- | :--- | :--- |
| **OpenAI** | `openai` | `openai/*` | Standard API key (`api_key`). |
| **Anthropic** | `anthropic` | `anthropic/*` | Standard API key (`api_key`). Works with both OpenAI-compatible and native Anthropic SDK routes. |
| **Google Gemini** | `gemini` | `gemini/*` | Google AI Studio API key (`api_key`). |
| **Google Vertex AI** | `vertex_ai` | `vertex_ai/*` | Uses `service_account_json` with required `project` and `location` fields. |
| **OpenRouter** | `openrouter` | `openrouter/*` | Standard API key (`api_key`). Query `GET /v1/models` to confirm which upstream slugs are active for your key. |
| **NVIDIA NIM** | `nvidia_nim` (`nvidia`, `nim`) | `nvidia_nim/*` | Standard API key (`api_key`). Hosted API Catalog and self-hosted NIM endpoints can require different endpoint fields in the form. |
| **Azure OpenAI** | `azure` | `azure/*` | Uses `api_key` or `azure_ad_token`, plus `api_base` and `api_version`. Confirm your Azure deployment names match your model routing setup. |
| **AWS Bedrock** | `bedrock` | `bedrock/*` | Available when enabled in your deployment. Uses the AWS credential or role fields shown in **Provider Credentials**. |

Confirm available models for your Zorveus API key with `GET /v1/models` or [the model catalog](https://www.zorveus.com/models) before sending production traffic. A wildcard policy alone does not mean every upstream model is enabled.

## Rotate or remove a key

Open **Provider Credentials** in the dashboard to update or delete a key. If an upstream provider rejects a key, rotate it with that provider first, then update the credential in Zorveus. Deleting a credential also revokes any explicit grants attached to it, so check which API keys depend on it first.

---

## Verify BYOK billing

Send a test request with your Zorveus API key and open **Usage** in the dashboard:

- Successful BYOK requests record `billing_mode: "byok_external"`.
- Your upstream provider bills your provider account directly. `sell_cost` shows the Zorveus wallet charge, including any configured platform fee.
- BYOK requests still count against reference-priced customer allowances on the API key.

For platform fees, wallet fallback, and multi-key priority, see [Key priority, rotation, and fallback](/startups/automatic-routing) and [BYOK costs](/wallet-and-billing/byok-costs).
