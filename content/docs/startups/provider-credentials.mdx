---
title: Provider credentials
description: Configure Bring Your Own Key credentials in the Zorveus dashboard.
---

Manage provider credentials in the Zorveus dashboard under **Provider Credentials**. Use a Zorveus API key for inference, not the upstream provider secret.

## Add a provider credential

1. Open your organization in the Zorveus dashboard.
2. Open **Provider Credentials**.
3. Select the provider and enter the credentials requested by the form.
4. Set the model policy and routing options shown in the dashboard.
5. Save the credential and check its validation status.

The dashboard lists supported providers and their required fields. Do not copy upstream secrets into application requests.

## Choose a routing mode

| Mode | Behavior |
| --- | --- |
| `auto_resolve` | The gateway may use the credential when its model policy matches. |
| `manual_grant_only` | The gateway uses the credential only for app connections that have an explicit grant. |
| `disabled` | The gateway does not resolve the credential. |

Configure routing and app-connection access in the dashboard. Lower `routing_priority` values are considered before higher values.

## Rotate or remove a credential

Use **Provider Credentials** in the dashboard to replace or remove upstream credentials. Check which app connections depend on a credential before removing it.

## Test inference and verify billing

Select an available model from [the model catalog](https://www.zorveus.com/models). Send an inference request with your Zorveus API key and open **Usage** in the dashboard to inspect the completed request.

- Successful BYOK requests record `billing_mode: "byok_external"`.
- Your upstream provider bills your provider account directly. `sell_cost` records the Zorveus wallet charge, including any configured platform fee.
- BYOK still consumes reference-priced customer allowance under your connection's policy.
- Adding a provider credential does not bypass model access rules configured on the app connection.

## Configure wallet fallback

Check `auto_fallback_to_wallet` before enabling a credential in production. When fallback is enabled, an eligible upstream failure can route through a managed wallet-funded path if one is available and your wallet has funds to reserve. Those fallback requests bill your Zorveus wallet.

For provider-specific setup, routing priority, and billing details, see [Provider integrations](/providers/overview), [Automatic provider routing](/startups/automatic-routing), and [BYOK costs](/wallet-and-billing/byok-costs).
