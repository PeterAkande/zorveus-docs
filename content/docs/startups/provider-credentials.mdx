Provider credentials hold encrypted upstream secrets owned by your organization. Zorveus validates a credential before storing it and returns only safe metadata and a secret fingerprint.

<KeyInserter type="service" label="Service Key Inserter" placeholder="zrv_svc_your_service_key" />

## Discover supported providers

Call `GET /provider-credentials/providers` to get the providers supported by Zorveus. The response lists current provider IDs, aliases, accepted secret kinds, and required provider configuration fields.

Do not treat the provider pages as a permanent model catalog. Use `GET /models` for the current dashboard model list and `GET /v1/models` for models available to an API key.

## Create a provider credential

<CodeGroup titles={["cURL", "Python"]}>

```bash
curl -X POST https://api.zorveus.com/provider-credentials/org-programmatic \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer zrv_svc_your_service_key" \
  -d '{
    "provider": "openai",
    "credential_name": "OpenAI production",
    "secret": "sk-proj-sample_upstream_key_123456789",
    "secret_kind": "api_key",
    "default_model_policy": ["openai/*"],
    "routing_mode": "auto_resolve",
    "routing_priority": 10
  }'
```

```python
import requests

response = requests.post(
    "https://api.zorveus.com/provider-credentials/org-programmatic",
    headers={
        "Content-Type": "application/json",
        "Authorization": "Bearer zrv_svc_your_service_key",
    },
    json={
        "provider": "openai",
        "credential_name": "OpenAI production",
        "secret": "sk-proj-sample_upstream_key_123456789",
        "secret_kind": "api_key",
        "default_model_policy": ["openai/*"],
        "routing_mode": "auto_resolve",
        "routing_priority": 10,
    },
)

print(response.json())
```

</CodeGroup>

The service key supplies the organization. Do not send `org_id` in the service-key request body.

## Choose a routing mode

| Mode | Behavior |
| --- | --- |
| `auto_resolve` | The gateway may use the credential when its model policy matches. |
| `manual_grant_only` | The gateway uses the credential only for app connections that have an explicit grant. |
| `disabled` | The gateway does not resolve the credential. |

Lower `routing_priority` values are considered before higher values. A matching policy such as `openai/*` does not override a disabled credential or a missing connection grant.

## Rotate or delete a credential

Rotate a service-key credential with `POST /provider-credentials/org-programmatic/{provider_credential_id}/rotate`. Send the replacement `secret` and `secret_kind`. Zorveus retires the previous secret version.

Delete it with `DELETE /provider-credentials/org-programmatic/{provider_credential_id}`. Deletion disables routing, retires active secret versions, and revokes connection grants. Create a replacement before deletion if traffic still depends on the credential.

## Common errors

| Code | Meaning |
| --- | --- |
| `zorveus_invalid_provider_credential` | Provider validation rejected the supplied secret or configuration. |
| `zorveus_provider_credential_config_required` | A provider-specific configuration field is missing. |
| `zorveus_provider_credential_already_exists` | The organization already has a credential with that name. |
| `zorveus_provider_credential_secret_required` | The secret is empty. |
| `zorveus_service_key_scope_required` | The service key lacks provider-credential write access. |
