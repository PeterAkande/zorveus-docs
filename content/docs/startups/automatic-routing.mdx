title: Automatic provider routing
description: Understand credential priority, BYOK selection, and optional wallet fallback.

Zorveus selects an eligible credential for the model you request. It does not choose a cheaper model or change your model ID automatically

## Configure eligible credentials

Add [provider credentials](/startups/provider-credentials) in the dashboard. A credential must be active, match the model's provider and allowed model policy, and be available to the app connection. `auto_resolve` credentials can be selected automatically. `manual_grant_only` credentials need an explicit connection grant

Explicit connection grants are considered before organization credentials available through automatic resolution. Within each group, lower `routing_priority` numbers come first. For example, `10` precedes `30`. Do not rely on equal-priority credentials receiving equal traffic

Credentials in quota cooldown are placed after healthy candidates. Cooldown does not mean the credential is permanently disabled or that every failing credential is excluded

## Understand wallet fallback

If no eligible BYOK credential resolves, the request uses the configured Zorveus-managed route and checks wallet funding

If a BYOK credential resolves, backup credentials can be attempted for eligible provider failures. Wallet fallback from that BYOK request requires `auto_fallback_to_wallet`, an available managed route, and enough wallet funds for the reservation. Disabling fallback does not create a BYOK-only model policy for requests that match no credential

Wallet fallback can change who pays for a request. A successful fallback is recorded as `billing_mode: "wallet"`. Successful BYOK usage is `byok_external`, with applicable platform fees. Check usage after testing both paths

Model-policy and customer-allowance failures are not a reason to bypass the selected plan. See [BYOK costs](/wallet-and-billing/byok-costs) and [Error handling](/platform/errors)
