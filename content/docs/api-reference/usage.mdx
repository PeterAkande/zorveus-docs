<KeyInserter type="api" label="API Key" placeholder="zrv_your_api_key" />

## Get key usage

<ApiEndpoint method="GET" path="/inference-keys/usage" auth="api_key" />

Send your inference key or scoped OAuth access token in the `Authorization` header. When using a routing key, add `X-Zorveus-Key-Alias` to inspect a specific member connection.

<CodeGroup titles={["cURL", "Python", "TypeScript"]}>

```bash
curl --fail-with-body https://api.zorveus.com/inference-keys/usage \
	-H "Authorization: Bearer zrv_your_api_key"
```

```python
import httpx

response = httpx.get(
    "https://api.zorveus.com/inference-keys/usage",
    headers={"Authorization": "Bearer zrv_your_api_key"},
)
usage = response.json()
print(f"Spent: ${usage['spent_this_period']} / ${usage['spend_cap']}")
```

```typescript
import { Zorveus } from "@zorveus/sdk";

const zorveus = new Zorveus({ apiKey: "zrv_your_api_key" });
const usage = await zorveus.getUsage();

console.log(`Spent: $${usage.spent_this_period} of $${usage.spend_cap}`);
```

<ApiRunner method="GET" path="/inference-keys/usage" />

### Response

```json
{
  "status": "active",
  "app_id": "app_123",
  "app_connection_id": "appcon_123",
  "currency": "USD",
  "period": "monthly",
  "spend_cap": "50.000000000000",
  "spent_this_period": "12.500000000000",
  "remaining_balance": "37.500000000000",
  "reset_at": "2026-12-01T00:00:00Z"
}
```

<ResponseField name="status" type="string" required>
  Status of the connection, such as `active` or `capped`.
</ResponseField>

<ResponseField name="app_id" type="string" required>
  Unique identifier of the application this key belongs to.
</ResponseField>

<ResponseField name="app_connection_id" type="string" required>
  Unique identifier of the specific connection routing this key's requests.
</ResponseField>

<ResponseField name="currency" type="string" required>
  Three-letter ISO currency code, typically `USD`.
</ResponseField>

<ResponseField name="period" type="string" required>
  Cap period, such as `daily`, `monthly`, or `total`.
</ResponseField>

<ResponseField name="spend_cap" type="string">
  The configured spend limit as a decimal string, or `null` if uncapped.
</ResponseField>

<ResponseField name="spent_this_period" type="string" required>
  Total amount spent by this key in the current billing window.
</ResponseField>

<ResponseField name="remaining_balance" type="string">
  Remaining spend before the key cap is reached, or `null` if uncapped.
</ResponseField>

<ResponseField name="reset_at" type="string">
  ISO 8601 timestamp for when the spend counter resets.
</ResponseField>

---

## Customer-level allowance vs key usage

`GET /inference-keys/usage` reports aggregate spending across the entire API key.

If you are tracking an individual customer's usage and quota, use [the product-user endpoint](/api-reference/product-users) with your server service key. That endpoint factors in customer-specific caps, one-time credits, and subscription anchor dates.
