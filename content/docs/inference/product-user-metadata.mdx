---
title: Track requests by customer
description: Send customer IDs, optional profile data, and request activity labels with your AI requests.
---

Send the signed-in customer's ID with each AI request. Zorveus uses it to track their spending and apply their allowance. The first request creates their customer record automatically.

Keep customer identity server-controlled. Derive the customer ID from your authenticated session state. Never allow browser clients to pass an unverified customer ID.

---

## Send the customer's ID

Pass the customer's ID in the `X-Zorveus-External-User-ID` header. Headers work across standard JSON requests and multipart file uploads:

<CodeGroup titles={["TypeScript (OpenAI SDK)", "Python (OpenAI SDK)", "cURL"]}>

```typescript
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.ZORVEUS_STARTER_KEY!,
  baseURL: "https://api.zorveus.com/v1",
});

const response = await client.chat.completions.create(
  {
    model: "openai/gpt-4.1-mini",
    messages: [{ role: "user", content: "Write a haiku" }],
  },
  {
    headers: { "X-Zorveus-External-User-ID": "customer_42" },
  },
);
```

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["ZORVEUS_STARTER_KEY"],
    base_url="https://api.zorveus.com/v1",
)

response = client.chat.completions.create(
    model="openai/gpt-4.1-mini",
    messages=[{"role": "user", "content": "Write a haiku"}],
    extra_headers={"X-Zorveus-External-User-ID": "customer_42"},
)
```

```bash
curl https://api.zorveus.com/v1/chat/completions \
  -H "Authorization: Bearer $ZORVEUS_STARTER_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Zorveus-External-User-ID: customer_42" \
  -d '{
    "model": "openai/gpt-4.1-mini",
    "messages": [{"role": "user", "content": "Write a haiku"}]
  }'
```

</CodeGroup>

When sharing an API client across multiple customer requests, set the ID on each call rather than setting client-level defaults.

## Add optional profile details

You can optionally send profile information to display readable customer names in your Zorveus dashboard:

```json
{
  "model": "openai/gpt-4.1-mini",
  "messages": [{"role": "user", "content": "Hello"}],
  "metadata": {
    "external_user_id": "customer_42",
    "product_user": {
      "display_name": "Alex Rivera",
      "email": "alex@example.com"
    }
  }
}
```

You can also pass these profile fields via HTTP headers:

```http
X-Zorveus-External-User-ID: customer_42
X-Zorveus-Product-User-Display-Name: Alex Rivera
X-Zorveus-Product-User-Email: alex@example.com
```

Profile details are for dashboard reporting and identification. Profile fields do not authorize a subscription plan or change customer limits. Your backend selects the plan's inference key.

## Attach business context to usage events

Use `usage_metadata` to label specific tasks (such as an agent reply, document indexing, or audio transcription). When your backend fetches customer activity via [Product-user activity](/startups/product-user-activity), Zorveus returns these saved fields with each request item.

Pass activity metadata using HTTP headers:

```http
X-Zorveus-External-User-ID: customer_42
X-Zorveus-Usage-Metadata: {"activity_label": "Drafting assistant", "activity_id": "reply_123"}
```

Or pass it in the request body under `metadata.usage_metadata`:

<CodeGroup titles={["cURL", "TypeScript (@zorveus/sdk)", "Python (zorveus)"]}>

```bash
curl https://api.zorveus.com/v1/chat/completions \
  -H "Authorization: Bearer $ZORVEUS_STARTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-4.1-mini",
    "messages": [{"role": "user", "content": "Reply to ticket"}],
    "metadata": {
      "external_user_id": "customer_42",
      "usage_metadata": {
        "activity_id": "reply_123",
        "activity_label": "Customer support reply",
        "project_id": "proj_support"
      }
    }
  }'
```

```typescript
import { Zorveus } from "@zorveus/sdk";

const client = new Zorveus({ apiKey: process.env.ZORVEUS_STARTER_KEY! });

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Reply to ticket" }],
  zorveusMetadata: {
    externalUserId: "customer_42",
    usageMetadata: {
      activity_id: "reply_123",
      activity_label: "Customer support reply",
      project_id: "proj_support",
    },
  },
});
```

```python
from zorveus import Zorveus

client = Zorveus(api_key=os.environ["ZORVEUS_STARTER_KEY"])

response = client.chat.completions.create(
    model="openai/gpt-4.1-mini",
    messages=[{"role": "user", "content": "Reply to ticket"}],
    user="customer_42",
    usage_metadata={
        "activity_id": "reply_123",
        "activity_label": "Customer support reply",
        "project_id": "proj_support",
    },
)
```

</CodeGroup>

`activity_label` and `activity_id` are application-defined. They do not alter pricing or deduplicate requests.

## Advanced metadata rules

### Header and body precedence

`X-Zorveus-Usage-Metadata` accepts a JSON-encoded object. The gateway merges header keys with `metadata.usage_metadata`. The body wins when both define the same key:

- Header: `{"channel": "web", "activity_id": "default"}`
- Body: `{"activity_id": "reply_123"}`
- Merged: `{"channel": "web", "activity_id": "reply_123"}`

### Size limits

The header, body object, and merged object must each fit within 4,096 UTF-8 bytes. The header must be an object (not an array or scalar). Values can contain strings, numbers, booleans, arrays, and nested objects. Invalid JSON or oversized payloads return HTTP 400 before a reservation is created.

### Scoping and upstream stripping

- **App scoping**: A customer ID is scoped to your Zorveus app. The same ID in another app is an independent customer record.
- **Provider stripping**: Zorveus strips all `X-Zorveus-*` headers and internal business metadata before forwarding requests to model providers (OpenAI, Anthropic, Google).
- **Request tracing**: Successful gateway responses include `x-zorveus-request-id` and, when a reservation is made, `x-zorveus-reservation-id` for audit logging.
