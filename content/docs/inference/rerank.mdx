---
title: Rank search results
description: Reorder search results by relevance to improve retrieval accuracy.
---

Reorder search results by relevance. Rerank models take an initial list of documents and rescore them against the user's query, giving you higher precision than vector similarity search alone.

<ApiEndpoint method="POST" path="/v1/rerank" auth="api_key" />

## Code examples

<CodeGroup titles={["TypeScript", "Python", "cURL"]}>

```typescript
const response = await fetch("https://api.zorveus.com/v1/rerank", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer zrv_your_api_key",
  },
  body: JSON.stringify({
    model: "cohere/rerank-v4.0-fast",
    query: "What is write-ahead logging?",
    documents: [
      "Write-ahead logging records transactions sequentially before disk writes.",
      "Redis is an in-memory key-value data store.",
      "PostgreSQL uses MVCC for concurrency control.",
    ],
    top_n: 2,
  }),
});

const data = await response.json();
console.log(data.results);
```

```python
import httpx

response = httpx.post(

```

## Request parameters

<ParamField name="model" type="string" required>
  The reranking model identifier, such as `cohere/rerank-v4.0-fast`.
</ParamField>

<ParamField name="query" type="string" required>
  The user search query or question to score candidate documents against.
</ParamField>

<ParamField name="documents" type="array" required>
  List of document strings to score and reorder.
</ParamField>

<ParamField name="top_n" type="integer">
  Number of most relevant documents to return. Defaults to the total number of documents.
</ParamField>

---

## Response format

```json
{
  "id": "rerank-01JABC123",
  "results": [
    {
      "index": 0,
      "relevance_score": 0.9824,
      "document": {
        "text": "Write-ahead logging records transactions sequentially before disk writes."
      }
    },
    {
      "index": 2,
      "relevance_score": 0.3412,
      "document": {
        "text": "PostgreSQL uses MVCC for concurrency control."
      }
    }
  ],
  "meta": {
    "billed_units": {
      "search_units": 1
    }
  }
}
```

<ResponseField name="results" type="array" required>
  Ranked list of document objects sorted in descending order of `relevance_score`.
</ResponseField>

<ResponseField name="results[].index" type="integer" required>
  The original 0-based position of the document in the request `documents` array.
</ResponseField>

<ResponseField name="results[].relevance_score" type="number" required>
  Relevance confidence score between 0.0 and 1.0.
</ResponseField>

## Customer spending limits

Rerank requests can be attributed to individual customer allowances using the customer ID header:

```http
X-Zorveus-External-User-ID: customer_42
```

If you fetch customer activity lists or show usage history in your product, add an optional activity label:

```http
X-Zorveus-Usage-Metadata: {"activity_label": "Search ranking"}
```

`X-Zorveus-Usage-Metadata` accepts any custom JSON object up to 4 KB. When your backend fetches your customer's usage list through [Product-user activity](/startups/product-user-activity), Zorveus returns these saved fields with each request item.

Or pass them in the request body under `metadata`:

```json
{
  "model": "cohere/rerank-v4.0-fast",
  "query": "What is write-ahead logging?",
  "documents": ["..."],
  "metadata": {
    "external_user_id": "customer_42",
    "usage_metadata": {
      "activity_label": "Search ranking"
    }
  }
}
```

Follow [Add customer usage limits](/getting-started/product-user-quickstart) to configure per-user allowances.
