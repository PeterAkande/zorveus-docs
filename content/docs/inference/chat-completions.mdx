Generate text, code, or structured answers from AI models with one endpoint.

<ApiEndpoint method="POST" path="/v1/chat/completions" auth="api_key" />

## Make a request

Pass your API key in the `Authorization` header and send a message.

<CodeGroup titles={["TypeScript (@zorveus/sdk)", "Python (zorveus)", "TypeScript (OpenAI SDK)", "Python (OpenAI SDK)", "cURL"]}>

```typescript
import { Zorveus } from "@zorveus/sdk";

const client = new Zorveus({
  apiKey: "zrv_your_api_key",
});

const completion = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [
    { role: "user", content: "Explain write-ahead logging (WAL) concisely." },
  ],
});

console.log(completion.choices[0].message.content);
```

## Read the response

The model returns a completion object. The generated text lives in `choices[0].message.content`:

```json
{
  "id": "chatcmpl-8xK9Lm...",
  "object": "chat.completion",
  "created": 1715000000,
  "model": "openai/gpt-4.1-mini",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Write-ahead logging (WAL) ensures database durability by writing transaction changes to an append-only log on disk before applying them to database files."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 17,
    "completion_tokens": 30,
    "total_tokens": 47
  }
}
```

The `usage` block reports the tokens consumed. Zorveus calculates cost from these counts and settles it against your wallet or active customer allowance.

## Request parameters

<ParamField name="model" type="string" required>
  The model ID to route the request to, such as `openai/gpt-4.1-mini`, `anthropic/claude-sonnet-5`, or `gemini/gemini-2.5-flash`.
</ParamField>

<ParamField name="messages" type="array" required>
  An array of message objects. Each object contains `role` (`system`, `user`, `assistant`, or `tool`) and `content`.
</ParamField>

<ParamField name="temperature" type="number">
  Controls randomness. Lower values are more deterministic. Some reasoning models reject this setting.
</ParamField>

<ParamField name="max_tokens" type="integer">
  Maximum tokens to generate. Reasoning models accept `max_completion_tokens` instead.
</ParamField>

<ParamField name="stream" type="boolean" default="false">
  When set to `true`, tokens stream back incrementally over Server-Sent Events. See [Stream a response](/inference/streaming).
</ParamField>

## Customer spending limits

If your application gives each customer their own AI allowance, you must attach the customer's ID to the request. Zorveus requires this ID to look up their balance and enforce their limit.

You can pass the customer ID as a header:

```http
X-Zorveus-External-User-ID: customer_42
```

Or pass it in the request body:

```json
{
  "model": "openai/gpt-4.1-mini",
  "messages": [{"role": "user", "content": "Hello"}],
  "metadata": {
    "external_user_id": "customer_42"
  }
}
```

In the Zorveus SDK:
- **TypeScript**: `zorveusMetadata: { externalUserId: "customer_42" }`
- **Python**: `user="customer_42"`

### Optional: attach custom usage metadata and customer names

You can pass custom keys inside `usage_metadata` (such as `activity_label`, `project_id`, or `feature`). When your backend fetches customer usage through [Product-user activity](/startups/product-user-activity), Zorveus returns these saved fields with each activity item so you can display an itemized breakdown to your users.

You can pass them using HTTP headers:

```http
X-Zorveus-External-User-ID: customer_42
X-Zorveus-Product-User-Display-Name: Alex Rivera
X-Zorveus-Usage-Metadata: {"activity_label": "Drafting assistant", "project_id": "proj_123"}
```

Or include them in the request body under `metadata`:

```json
{
  "model": "openai/gpt-4.1-mini",
  "messages": [{"role": "user", "content": "Hello"}],
  "metadata": {
    "external_user_id": "customer_42",
    "product_user": {
      "display_name": "Alex Rivera",
      "email": "alex@example.com"
    },
    "usage_metadata": {
      "activity_label": "Drafting assistant",
      "project_id": "proj_123"
    }
  }
}
```

| Field | Header alternative | Required? | Purpose |
| :--- | :--- | :--- | :--- |
| `external_user_id` | `X-Zorveus-External-User-ID: customer_42` | **Required** | Identifies the customer and settles against their allowance. |
| `product_user.display_name` | `X-Zorveus-Product-User-Display-Name: Alex Rivera` | *Optional* | Shows the customer's readable name in your dashboard. |
| `product_user.email` | `X-Zorveus-Product-User-Email: alex@example.com` | *Optional* | Shows the customer's email in your dashboard. |
| `usage_metadata` | `X-Zorveus-Usage-Metadata: {...}` | *Optional* | Custom JSON data (up to 4 KB) returned when you fetch customer usage through [Product-user activity](/startups/product-user-activity). |
