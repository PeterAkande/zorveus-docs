---
title: OAuth errors
description: Handle consent errors, token exchange failures, and rejected inference tokens.
---

Authorization, token exchange, and inference have different failure paths. Handle each where it occurs

## Browser authorization

Zorveus validates the client, exact registered redirect URI, scopes, and PKCE challenge before consent. Invalid authorization requests can stay on a Zorveus-hosted error page, so your callback is not guaranteed to run

When a user denies consent, the callback includes `error=access_denied` and the original `state`. Check state on error callbacks as well as successful callbacks

A model scope must start with `models:`, for example `models:*` or `models:openai/*`, alongside `inference:write`. A bare `openai/*` is not a model scope

## Token exchange

`POST /oauth/token` returns structured Zorveus errors. For example, a verifier mismatch returns HTTP `400`:

```json
{
	"error": {
		"code": "zorveus_invalid_code_verifier",
		"message": "OAuth code_verifier does not match the authorization code."
	}
}
```

Branch on `error.code` and HTTP status. Message text is for display and can change

| Code | Action |
| --- | --- |
| `zorveus_invalid_code_verifier` | Restart authorization with a fresh verifier and its S256 challenge |
| `zorveus_oauth_code_expired` | Start authorization again |
| `zorveus_oauth_code_consumed` | Recover the first token response or start authorization again |
| `zorveus_invalid_client_secret` | Check the confidential client's server-side secret |
| `zorveus_client_secret_required` | Send the confidential client's secret from its backend |
| `zorveus_redirect_uri_mismatch` | Send the exact redirect URI used to obtain the code |
| `zorveus_model_scope_required` | Request at least one `models:` scope |

## Inference after authorization

Use the returned token for that user's requests. An unknown token returns `401`. An inactive token returns `403` with `zorveus_key_inactive`. Model policy or caps can return `403`, and insufficient wallet funding can return `402`

Prompt reconnection for invalid authorization. For funding or cap failures, direct the user to their funding account or connection settings. Do not treat every `403` as revocation. The gateway can nest its structured Zorveus code inside `error.provider_specific_fields.error`. See [Error handling](/platform/errors)
